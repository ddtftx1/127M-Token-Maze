你正在维护一个纯前端 3D 迷宫游戏项目（Three.js r160 UMD，无构建工具，模块用 IIFE + 全局 MG 命名空间组织）。现有文件：index.html、css/style.css、js/{settings,audio,maze,pathfinding,player,input,ranking,shop,replay,ui,main}.js。

════════════════════════════════════════
【全局硬约束，优先级最高】竖屏与桌面端零回归
════════════════════════════════════════

本次所有改动只允许影响「手机横屏」这一种场景。以下场景的视觉与交互必须与改动前 100% 一致，任何像素偏差都视为不合格：

1. 所有竖屏（orientation: portrait），无论高度多少，包括但不限于 360×640、375×667、390×844、393×852、412×915、428×926、768×1024。竖屏下不允许出现任何两列、网格、限高、字号缩小等横屏效果。
2. 桌面宽屏（高度 > 640px 的横屏窗口），例如 1920×1080、1440×900、1366×768 中高度大于 640 的、1280×800。这些必须继续走「单列 620px 居中面板」的原有布局。
3. 平板横屏（如 iPad 1024×768、1180×820）高度 > 640，同样不属于本次横屏适配范围，保持桌面式布局即可。
4. 竖屏与桌面端的所有 HUD 控件位置、尺寸、间距、点击热区一律不动。

实现手段：横屏适配块必须放在 style.css 文件末尾，只通过 @media (orientation: landscape) and (max-height: 640px) 触发；主菜单的列容器 .menu-grid 在默认（竖屏）状态下必须是 display: block，绝不能在未加媒体查询时变成 grid。

════════════════════════════════════════
任务一：修复「暂停 → 设置 → 返回」后 HUD 消失的 bug
════════════════════════════════════════

【复现路径】
游戏中（state=playing）点击 ⏸ → 弹出暂停菜单 → 点击「设置」→ 进入设置面板 → 直接点击「返回」。此时透过暂停菜单的半透明背景看不到 HUD；若再点「继续游戏」，HUD 彻底消失，且此后无法恢复。竖屏横屏都能复现，横屏下更明显。

【根因】
ui.js 的 closeSettings() 里，settingsFrom==='pause-menu' 分支只调用了 show('pause-menu')，没有恢复此前被 showSettings() 隐藏的 HUD；resumeGame() 也没有兜底 show('hud')。对比 settingsFrom==='hud' 分支是有 show('hud') 的，属于分支不对称遗漏。

【修复要求】
1. js/ui.js 的 closeSettings() 中，settingsFrom === 'pause-menu' 分支里，在 show('pause-menu') 之前补一行 show('hud')，使「从暂停进设置再返回」后的界面状态与「直接暂停」完全一致（暂停菜单覆盖在可见的 HUD 之上）。
2. js/main.js 的 resumeGame() 中，在 hidePause() 之后、Game.state = 'playing' 之前补一行 MG.UI.show('hud')，作为兜底：无论从哪条路径恢复游戏，HUD 都必须可见。以后新增暂停入口也不会再踩同样的坑。
3. 修复后自查其他 hide('hud') 的位置是否都有恢复路径：
   - showGame() 里有 show('hud')，正常。
   - showWin() / showMainMenu() 隐藏 HUD 后被新界面替代，无需恢复，正常。
   - 道具面板不隐藏 HUD，正常。
   若发现遗漏请一并补上，并在回复中说明。

1. 不要修改任何 js 逻辑（任务一的 bug 修复除外）。input.js 里对 HUD 容器的引用、main.js 里的状态机、ui.js 里所有 id 查找都依赖现有 DOM 结构，重构 index.html 时所有 id 和 class 必须原样保留，只新增 .menu-hero / .menu-grid / .menu-col 三个包裹层。
