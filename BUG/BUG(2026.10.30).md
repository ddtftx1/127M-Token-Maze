<h2 id="bug-017">BUG-017 · Win7 / 老系统 Emoji 显示白框或单色</h2>

- **发现日期**：2026-10-30
- **状态**：✅ 已修 / 2026-10-30
- **优先级**：P1（不影响逻辑，但界面在目标系统上不可读）
- **模块**：`index.html`、`js/ui.js`、`js/main.js`、`js/shop.js`、新增 `js/icons.js`、`css/style.css`

### 现象

在 Win7 上打开游戏，所有按钮和标题里的图标位置变成**空心白框（tofu）**；
Win10 上部分字符能显示但只有单色，与设计稿的彩色图标不一致。

### 复现

Win7 + 任意浏览器打开 `index.html` → 主菜单的「本地排行榜 / 商店 / 成就 / 每日挑战」
等按钮 → 图标位置显示为方框；商店卡片、成就列表、胜利界面同样。

### 根因分析

游戏用 Emoji 字符（🏆 🏪 🗺 🎒 👻 💰 🧭 ⚡ 📅 🎉 🤫 ⏸ 🏅 ✅ 🔒 🎥）当图标。
这类字符依赖系统字体：

- Win7 的 Segoe UI Symbol 不含彩色 Emoji，Unicode 覆盖也不全 → 无字形回退到 tofu；
- Win10 早期版本的 Segoe UI Emoji 只有单色轮廓；
- 结果完全由用户系统决定，前端无法兜底。

共 39 处（`index.html` 18 / `ui.js` 14 / `main.js` 4 / `shop.js` 3——含文字串里的 1 处）。

### 修复

1. 新增 `js/icons.js`：把 `svg/` 下 16 个 Noto Emoji 彩色 SVG 的文本内容
   **内联为 JS 字符串**（`MG.Icons.svg = { trophy: '<svg…>', … }`）。
   内联的原因：项目要支持 `file://` 双击打开，该协议下 `fetch` / `XMLHttpRequest`
   读本地 `.svg` 会被 CORS 拦死。
2. `index.html` 里 20 处静态位置改为 `<span class="svg-icon" data-icon="trophy"></span>`；
   `boot()` 中调用 `MG.UI.fillIcons()` 一次性填充（幂等，带 `data-icon-done` 标记）。
3. 动态生成的列表（排行榜 / 商店 / 道具 / 成就 / 胜利结算 / 回放条）改用
   `MG.UI.iconHtml(key)` 拼进 `innerHTML`；`MG.UI.icon(key)` 返回原始 SVG 字符串。
4. `shop.js` 的 `ITEMS[*].icon` 由 Emoji 改为 key 名。
5. `css/style.css` 增加 `.svg-icon`（`1em` 方块、`vertical-align: -0.125em`）
   与 `.svg-icon > svg { width/height: 100% }`。
6. 新增 `THIRD_PARTY.md` 声明 Noto Emoji（Apache-2.0）。

### 关键坑：内联 SVG 的 id 冲突

Noto 的每个文件内部带 `id` 以及 `url(#id)` / `xlink:href="#id"` 引用（渐变、裁剪、mask）。
同一个图标在页面上出现多次时（例如奖杯同时出现在「本地排行榜」按钮、「成就」按钮、
成就页标题、成就 toast 里），后插入的实例会覆盖先插入实例的同名 id，
表现为**第一个图标的渐变串到后面所有图标上，甚至完全变黑/透明**。

修复方式：`MG.UI.iconSvg()` 在插入前给每个实例的 `id="X"` 与
`url(#X)` / `xlink:href="#X"` / `href="#X"` 统一加唯一后缀 `__i<序号>`。
这是纯字符串替换，不改图形内容。

### 验证

- 16 个图标逐个检查：`id` 无重复、`url(#)` 与 `href="#` 引用全部能在**本实例内**解析到
  （`t1-icons.js`，18 项断言）。
- 同一图标连续取两次（`iconHtml('trophy')` ×2）：两组 `id` 完全不重叠。
- `fillIcons()` 幂等：重复调用不会重复插入、也不会重复叠加 `svg-icon` 类名。
- HTML 结构：109 个 `id` 无重复，无未闭合标签。

### 备注

`⛶ ⚙ ✖ ▶ ↻` 属于跨平台支持良好的普通符号，按需求保留字符形式，没有换成图标。
`js/icons.js` 约 99KB（图形本体 92KB），一次性解析、零网络请求，不引入构建步骤。

**素材修正（2026-10-30 真机测试后发现，补充记录）**：`svg/摄像头.svg` 的原始导出文件里
包含**两个** SVG 根节点（`1F3A5` 摄像机 + `1F3A6` 电影摄影机），内联后两个图形都会渲染，
第二个溢出 1em 图标框——表现为回放条「跟随」按钮上多出一个图标。
同时该文件自带一块 128×128 白色背景矩形（其余 15 个图标都是透明底），在深色 UI 上是一块白方块。
处理：只保留摄像机图形，删除白底矩形，重新生成 `js/icons.js`（101,267 → 99,018 字节）。
修改同时落在源文件 `svg/摄像头.svg` 与内联产物上，并已按 Apache-2.0 要求在 `THIRD_PARTY.md` 标明。

<h2 id="bug-018">BUG-018 · 老内核退出全屏后误入手机横屏布局、右侧出现整页白滚动条</h2>

- **发现日期**：2026-10-30
- **状态**：✅ 已修 / 2026-10-30
- **优先级**：P0（布局整体错乱，游戏不可玩）
- **模块**：`css/style.css`、`js/main.js`

### 现象

Win7 + Chrome 49：全屏游戏正常；**退出全屏**后页面突然变成手机横屏的紧凑布局
（主菜单变两列、按钮缩小、HUD 挤在一起），并且**右侧多出一条整页的白色滚动条**。

### 复现

1. 桌面浏览器把窗口高度拖到 640px 以下（或全屏后退出，窗口高度本就 ≤640）；
2. 页面立刻切换成"手机横屏"样式；
3. 同时出现整页白条，面板贴边、间距消失。

### 根因分析

两个独立原因叠加：

1. **媒体查询没有设备判定**：
   `@media (orientation: landscape) and (max-height: 640px)` 只看"横屏 + 矮"，
   桌面浏览器窗口高度 ≤640px 完全命中 → 套用手机横屏的重排布局。
2. **`inset` 与 `env()` 在 Chrome 49 下无效，且失效方式很隐蔽**：
   - `inset: 0` 是 Chrome 87 才有的简写，老内核直接丢弃该声明 →
     `.screen` / `#app` 这类 `position: fixed` 的容器没有四边定位，被撑出视口 → 白滚动条。
   - `--safe-t: env(safe-area-inset-top, 0px)` 会被当成合法自定义属性**接受**，
     但代入 `calc()` 时 `env()` 无法解析 → 整条 `calc()` 无效 → `padding` / `top` /
     `max-height` 被重置为初始值（**不会**回退到上一条声明，这是和普通属性失效最大的区别）。

### 修复

1. 媒体查询补设备判定：
   `@media (orientation: landscape) and (max-height: 640px) and (hover: none) and (pointer: coarse)`
   —— 只有触屏设备（粗指针、无悬停）才进入紧凑布局。`hover` / `pointer` 是 Chrome 41+
   的标准媒体特性，老内核照样能正确判定。
2. `inset: 0` 共 8 处全部展开为 `top / right / bottom / left: 0`。
3. 启动期特性检测 `applyLegacyClasses()`（`main.js`，`boot()` 第一步执行），
   用 `CSS.supports()` 检测 → 给 `body` 挂 class：

   | class | 检测项 | 降级手段 |
   |-------|--------|----------|
   | `legacy-env` | `padding: env(safe-area-inset-top)` | `--safe-t/b/l/r` 统一按 `0px` 处理 |
   | `legacy-inset` | `inset: 0` | 已在上一步展开为四边 longhand |
   | `legacy-gap` | flex 容器的 `gap` | 相邻兄弟选择器补 `margin` |
   | `legacy-dvh` | `height: 100dvh` | 限高规则原有 `100vh` 兜底声明接管 |

4. `legacy-env` 下另给 `.hud-top`（`top: 8px`）与 `.toast`（`bottom: 34%`）显式兜底，
   不依赖变量替换，便于老内核上直接排错。

> 关于"安全区降级"的实现选择：需求举例是逐条写死数值（`.toast { bottom: 34% }`）。
> 这里改为把四个 `--safe-*` 变量按 `0px` 处理 —— 计算结果与逐条写死完全一致
> （`calc(34% + 0px)` = `34%`），但不必为全站 30 多处 `calc()` 各复制一份规则，
> 也不会漏掉某处。文档点名的两处含义仍然显式保留。

### 验证

- 静态：`css/style.css` 无残留 `inset:` 简写；`top/right/bottom/left: 0` 展开 8 组以上；
  大括号配平（1372 行）。
- 四个 `legacy-*` class 均有 `CSS.supports` 检测语句与对应样式块；
  `boot()` 第一句即调用 `applyLegacyClasses()`（早于设置加载与 UI 渲染，避免先按现代样式画一遍再跳变）。
- 现代浏览器路径不受影响：`CSS.supports` 全部为真 → 不挂任何 class → 样式与改动前逐字节一致。

### 备注

`legacy-gap` 的精度限制：`CSS.supports` 只能验证"属性是否存在"，无法区分 flex 与 grid。
Chrome 57~83 的 grid 已支持 `gap`、flex 尚未支持，会被误判为"支持"，
表现为 flex 子元素贴在一起（无间距但不错位）。目标环境 Chrome 49 判定正确，可接受。

<h2 id="bug-019">BUG-019 · 回放模式点击画面误锁鼠标、按 P 直接退出回放</h2>

- **发现日期**：2026-10-30
- **状态**：✅ 已修 / 2026-10-30
- **优先级**：P1
- **模块**：`js/input.js`、`js/main.js`

### 现象

1. 进入回放后，**点击画面**会锁定鼠标指针（光标消失、鼠标变成转视角），
   退出回放前都无法正常操作页面；
2. 回放中按 **P** 不是暂停/继续，而是**直接退出回放**弹回胜利界面；
3. 触屏设备上滑动转视角、松手时会被判定为"点击"。

### 复现

胜利界面 → 「▶ 回放本局」→ 点画面（指针被锁）→ 按 P（回放直接结束）。

### 根因分析

`input.js` 的点击处理是"无条件锁指针"，不区分游戏状态：

```js
node.addEventListener('click', function () {
  if (!self.pointerLocked && !document.hidden) self.requestPointerLock();
});
```

而 P 键走的是通用暂停回调 `onPause`，`main.js` 里该回调在 `replay` 状态下的分支是
`exitReplay()` —— 于是 P 变成"退出回放"而不是"暂停"。
另外触屏上手指抬起后浏览器会补发一次合成 `click`，转视角松手即误判。

### 修复

1. `input.js` 新增两个注入钩子（不反向依赖 `main.js`，保持"模块顺序即依赖顺序"）：
   - `getState`：读取当前状态（`menu/loading/playing/paused/win/replay`）；
   - `onToggleReplayPause`：回放的暂停/继续。
2. 点击语义改为：
   - 触摸产生的合成 `click`（距最近一次 `touchstart` / `touchend` < 500ms）直接忽略；
   - 仅"悬停 + 精细指针"设备（`matchMedia('(hover: hover) and (pointer: fine)')`）参与；
   - `replay` → 触发 `onToggleReplayPause`，**不请求 Pointer Lock**；
   - 其他非 `playing` 状态（菜单/暂停/胜利/加载）→ 不请求 Pointer Lock；
   - `playing` → 保持原行为。
3. P 键：`replay` 状态下触发 `onToggleReplayPause`，其余状态保持原 `onPause`。
   ESC 保持原逻辑（回放中 ESC = 退出回放）。
4. `main.js` 注入：
   ```js
   Game.input.onToggleReplayPause = function () { if (Game.state === 'replay') toggleReplayPause(); };
   Game.input.getState = function () { return Game.state; };
   ```

### 验证

- 无头实跑 15 项断言（`t2-input.js`，真实加载 `input.js` 并构造 `Input` 实例）：
  - `replay` 点击 → 触发 1 次暂停回调、Pointer Lock 请求 0 次；
  - `playing` 点击 → 请求 Pointer Lock 1 次、不触发回放回调；
  - `menu / paused / win / loading` 点击 → 均不请求 Pointer Lock；
  - `touchstart` 后 500ms 内的 click 被忽略，超过 500ms 恢复正常；
  - `hover: none` 设备点击不锁指针；
  - P 键：`playing` 走 `onPause`；`replay` 走 `onToggleReplayPause` 且不再走 `onPause`
    （即不会再意外退出回放）；
  - `getState` 未注入时按 `playing` 处理（向后兼容）。

### 备注

`_lastTouchTime` 在 `document` 上以 `touchstart` / `touchend` 两个事件更新（被动监听），
不拦截事件本身，不影响既有触摸逻辑（BUG-013 / BUG-014 的修复不受影响）。

<h2 id="bug-020">BUG-020 · 通关后的成就提示与音效在 1.2 秒内离开本局时丢失</h2>

- **发现日期**：2026-10-30
- **状态**：✅ 已修 / 2026-10-30
- **优先级**：P1（成就解锁了但玩家不知道，且音效一起丢）
- **模块**：`js/main.js`

### 现象

通关解锁成就后，如果在 1.2 秒内点「再玩一次 / 返回主菜单」，
成就 toast（🏆 解锁成就：xxx）和成就音效**再也没有出现过**，
玩家只能去成就页自己发现。

### 复现

简单难度 40 秒内通关（解锁「疾风步」）→ 立刻点「返回主菜单」→ 主菜单无任何成就提示。

### 根因分析

`onVictory()` 用一个 1.2 秒的 `setTimeout` 播报成就，而 `restartGame()` / `playAgain()` /
`backToMenu()` 都会先调用 `clearAchieveToastTimer()` 把定时器清掉。
清定时器本身是必要的（避免 toast 掉到新一局里），但成就名只存在于那个闭包里，
定时器一清，待播报的内容就**彻底丢失**——成就其实已经写进 `localStorage`，
只是提示与音效再也不会播放。

### 修复

1. `onVictory()`：先把成就名存进 `Game._pendingAchieveToast`，再设定时器；
   定时器回调改为调用统一的 `flushAchieveToast()`。
2. `clearAchieveToastTimer()`：**只清定时器**，不清挂起数据（并在注释里写明原因）。
3. `flushAchieveToast()`（新增）：存在挂起成就时播 `toast` + `Audio.achieve()`，
   然后清空挂起状态；无挂起时什么都不做（幂等）。
4. `backToMenu()`：清定时器后立即 `flushAchieveToast()` —— 回到菜单后
   不会再有"下一局开局 toast"，必须当场补发。
5. `buildLevel()` 末尾（开局种子 toast 之后）：若存在挂起成就，
   `setTimeout(flushAchieveToast, 2200)` 等开局 toast 播完再补发，避免两条 toast 互相覆盖。

三条离开路径（返回菜单 / 再玩一次 / 重开）现在都收敛到同一份挂起数据上。

### 验证

- 从 `main.js` 中提取 `clearAchieveToastTimer` 与 `flushAchieveToast` 的真实函数体，
  在沙箱里执行 17 项断言（`t3-achieve.js`）：
  - 清定时器后 `_pendingAchieveToast` 仍在（2 条）；
  - `flush` 弹 1 条 toast（HTML 模式、含成就名）+ 播 1 次音效，随后清空挂起；
  - 无挂起时再 `flush` 无副作用；
  - 调用点顺序：`onVictory` 先挂起后设定时器；`backToMenu` 先清后补；
    `buildLevel` 的补发排在开局种子 toast 之后且延迟 2200ms。

### 备注

挂起数据是**内存态**，不写 `localStorage`：成就的持久化仍由
`MG.Settings.unlockAchievement()` 负责（已解锁不会重复解锁），
这里只是"延迟播报"，刷新页面丢失不影响成就本身。

<h2 id="bug-021">BUG-021 · 地图道具的卷轴杆与地图板旋转不同步</h2>

- **发现日期**：2026-10-30（真机观察）
- **状态**：✅ 已修 / 2026-10-31（真机回归通过）
- **优先级**：P1（曾因真机回归未通过临时上调为 **P0**，定位为副本未同步后已闭环，恢复 P1）
- **模块**：`js/maze.js` → `MazeView.prototype.update()`（**唯一改动点**；`build()` / `tryCollectMap()` / `setColorblind()` / `applyTheme()` / `dispose()` 均未改）

### 现象

地图卷轴悬空自转时，平板在转、两根卷轴杆却不转。板边周期性地从两根杆之间"缩进去"，
角度越大缝隙越明显（约 60° 时 0.155、90° 时 0.28 个世界单位），看起来像**转轴和地图分开了**。

### 复现

任意难度进入游戏 → 找到地图卷轴并走近（**不要拾取**）→ 静观 3 秒以上 →
平板持续自转，杆固定在两侧不动，两者之间不断出现又消失的缝隙。

### 根因分析

`build()` 里 `board`（`BoxGeometry(0.62, 0.46, 0.06)`，半宽 0.31，`y=1.12`）与
`rodL` / `rodR`（`x = ±0.36`，`y=1.12`）是 `mapGroup` 下的三个**平级** Mesh；
而 `update()` 只写了：

```js
mi.board.rotation.y += dt * 1.2;   // 只转板
```

板绕**自身几何中心**转 θ 后，两端在 X 方向的投影变成 `±0.31·cosθ`，
杆仍钉在 `±0.36` 不动，两者间距必然为 `0.31 - 0.31·cosθ + 0.05`，
θ 越大缝越大，视觉上就是"轴和地图分开"。

### 修复

把自转的作用对象从 `board` 换到整个 `mapGroup`（**一行**）：

```js
// 地图道具：漂浮 / 自转 / 呼吸光
if (this.mapItem && !this.mapItem.collected) {
  var mi = this.mapItem;
  // 上下浮动：position 在父空间平移，与下面的 rotation 互不覆盖
  mi.group.position.y = Math.sin(this.time * 2.2) * 0.08;
  /* 自转作用在 mapGroup 整体上，而不是只转 board（BUG-021）。
     只转 board 时：板绕自身几何中心转，两端在 X 方向的投影变成 ±0.31·cosθ，
     而两根杆固定在 ±0.36，θ 越大缝隙越明显（θ=60° 约 0.155，θ=90° 约 0.28），
     看起来就是"轴和地图分开了"。整体自转后杆与板的相对位置是常数，任何角度都贴合。
     对其它成员无副作用：mapRing 是水平圆环（绕 Y 轴对称，转了看不出来）、
     glow 与 mapLight 都在中轴 x=0,z=0 上（绕 Y 位置不变）、
     色盲 Sprite 也在中轴且始终面向相机（公告板，父级旋转不影响其朝向）。 */
  mi.group.rotation.y += dt * 1.2;
  var gsc = 1 + Math.sin(this.time * 3.4) * 0.22;
  mi.glow.scale.set(gsc, gsc, gsc);
  if (mi.ring) mi.ring.rotation.z += dt * 0.7;
}
```

`build()` 的道具结构保持原样（未新增子 Group、未调整杆/板位置），
所以所有子对象的世界坐标与改动前**逐位一致**。

### 为什么整体自转对其余成员是安全的

| 成员 | 为什么不受影响 |
|------|----------------|
| `mapRing` | `rotation.x = -90°` 的水平圆环，对称轴就是 Y，绕 Y 旋转无视觉变化 |
| `glow` | 球体，本地坐标在 `x=0, z=0` 中轴上，绕 Y 旋转后世界位置不变 |
| `mapLight` | 点光源在中轴，点光源本身没有方向性 |
| 色盲 Sprite | 本地坐标居中轴 `x=0, z=0`，且是公告板（始终面向相机），父级绕 Y 旋转既不改变其世界位置也不改变朝向 |
| 拾取判定 | `tryCollectMap()` 用 `it.world` 固定世界坐标，与旋转完全无关 |
| 上下浮动 | `position` 是父空间平移、`rotation` 作用于子对象，两者互不覆盖 |

没有采用"给卷轴单独加一层子 Group"的写法：效果等价，但那样要改 `build()` 的场景结构，
而整体自转天然没有副作用，改动面更小、更容易 review。

### 验证

用**真实 three.js**（`assets/three.min.js` 直接在 vm 里加载）无头构造 `MazeView`，然后：

1. **结构**：`board` / 两根圆柱杆 / `glow` / `ring` / `PointLight` 全部直接挂在 `mapGroup` 下；
   `mapGroup` 之下没有新增的子 Group；`mapItem` 上没有额外字段；
2. **世界坐标不变**：板 `y=1.12`、两杆相对 `mapGroup` 的 `x=±0.36`、`y=1.12`；
3. **核心不变量**：扫 6 个旋转角（0 / 0.4 / 1.2 / 2.5 / 3.9 / 5.7 rad），把
   "杆中心 − 板中心"分解到板的**宽轴方向**与**垂直方向**：
   - 沿板宽投影恒为 `0.36`（误差 < 1e-6）
   - 垂直分量恒为 `0`（误差 < 1e-6）
   → 任何角度下杆都贴在板的两端；
4. **反向证明判定有效**：故意只转 `board` 90°（模拟修复前），同一套判定立刻报出
   沿板宽偏离 0.36 → 0.031、垂直偏移 0.2+，说明上面两条断言确实能抓到原 BUG；
5. **中轴成员**：`glow` / `ring` 在旋转前后世界位置差值 < 1e-6；
6. **色盲 Sprite**：挂在 `mapGroup`（原逻辑未改）、`y=2.15`、`x=z=0`；
   4 个角度下世界位置不动（< 1e-6）；
7. **浮动与自转并存**：`view.update(0.016)` 后 `position.y == sin(time*2.2)*0.08`、
   `rotation.y` 恰好 `+0.016*1.2`，`glow` 呼吸与 `ring` 自转都仍在推进；
8. **拾取行为不变**：超距离 `false`、入半径 `true`、拾取后 `collected=true` 且
   `group.visible=false`、重复拾取 `false`；
9. **源码级**：`mi.board.rotation.y` 已不存在、`mi.group.rotation.y += dt * 1.2` 存在、
   源码里没有新增子 Group；
10. `node --check js/maze.js` 通过。
