<h2 id="bug-022">BUG-022 · 先用道具解锁小地图后，地图卷轴无法拾取</h2>

- **发现日期**：2026-10-31
- **状态**：✅ 已修 / 2026-10-31
- **优先级**：P1（不阻断整局，但"先解锁、后捡卷轴"这条路径上功能完全不可用，且模型永久残留）
- **模块**：`js/main.js`（`loop()` 的 6.5 拾取分支、`buildBestPath()` 的目标收集）

### 现象

先通过道具面板使用「小地图解锁」，再走到本局地图卷轴的放置点：卷轴**仍然在原地缓慢自转**
（自转是正常表现），但贴身站上去**不会消失、不会入库、也没有任何提示**，道具面板里的
`mapUnlock` 数量不变 —— 看起来就像一张永远捡不起来的贴图。

### 复现

1. 任意难度进入游戏；
2. 按 F 打开道具面板 → 使用「小地图解锁」（商店购买的道具与拾取获得的道具等价）；
3. 打开小地图方向，走向本关地图卷轴的位置；
4. 贴到卷轴上：模型不消失、无 toast、`mapUnlock` 库存不变。

**预想结果**：可以拾取该地图，获得一个对应道具。
**实际结果**：无法拾取，也无法获得道具。

### 根因分析

`js/main.js` 原拾取分支（第 6.5 步）：

```js
if (!Game.mapFound && Game.mazeView.tryCollectMap(Game.player.pos.x, Game.player.pos.z, 1.2)) {
```

`&&` 短路求值：`Game.mapFound` 已为 `true` 时**整段不执行** —— 不判定距离、不隐藏模型、
不入库、不提示。玩家用道具解锁后 `mapFound` 就是 `true`，于是这条路径被彻底堵死。

**迷宫层无罪**：`MazeView.prototype.tryCollectMap()` 完全不读 `mapFound`。
无头实测（THREE 桩加载 `js/maze.js`，直接 `prototype.call`）：

```
A 未解锁时 tryCollectMap = true | collected = true | visible = false
B 已解锁时 tryCollectMap = true | collected = true | visible = false
```

两次都正常返回 `true` 并隐藏模型，说明拦截发生在调用方。

**引入时间**：2026-10-30 的 A 改造（"拾取进背包，不直接解锁小地图"）。
改造前 `Game.mapFound` **只在拾取那一刻**才被置为 `true`，该守卫不可达；
改造后玩家可以在拾取前用道具把它置为 `true`，守卫就变成了死条件。

**同根因的连带处**：`buildBestPath()` 收集目标时同样带 `&& !Game.mapFound`，
导致本局已解锁时「最佳路径」不会把卷轴算进路径目标 —— 与本局实际可拾取的行为不一致。

### 修复

把 `mapFound` 的角色从"是否进入分支"降级为"是否刷新小地图状态"：

1. 拾取分支去掉 `!Game.mapFound &&`，只要进入半径就入库；
2. 分支内按 `Game.mapFound` 分流：
   - **已解锁**：只 toast「已获得地图道具（库存 +1）」，小地图状态一个字不动。
     **绝不调用 `updateMinimapLock(true, …)`** —— 那会把已解锁的小地图重新锁上，
     HUD 距离信息与指南针距离一起消失，比原 bug 更严重；
   - **未解锁**：维持原行为（清空 `Game.mapHint` → `updateMinimapLock(true, '')` → 保持锁定）；
3. `buildBestPath()` 去掉 `&& !Game.mapFound`，自动寻路与本局实际可拾取行为一致。

### 验证

- **分支语义（真实代码验真）**：从 `js/main.js` 抽出 6.5 分支源码（不是复制品）注入 mock 执行：
  | 场景 | 断言 |
  |---|---|
  | 未解锁 + 进入半径 | 入库 1 次（`mapUnlock` ×1）→ 锁态刷新 1 次且 `locked=true` → `mapHint` 清空 → toast「…可在道具面板中使用」→ HUD 刷新 1 次 → 音效 1 次 |
  | 已解锁 + 进入半径（BUG-022 场景） | 仍进入判定 → 入库 1 次 → **`updateMinimapLock` 调用 0 次** → `mapHint` 不被改写 → toast「已获得地图道具（库存 +1）」 |
  | 未进入半径 | 不入库、不动小地图、不刷 HUD |
  | 钱包不可写 | 告警 1 次，仍给出拾取提示，仍不动小地图 |
- **迷宫层回归**：`tryCollectMap` 半径内 `true` / 半径外 `false` / 重复拾取 `false` / 函数体内不含 `mapFound`。
- **目标收集**：`buildBestPath()` 的卷轴目标行不再含 `!Game.mapFound`，附近有 BUG-022 溯源注释。
- **迷宫生成 + A\***：3 难度 × 2 算法 × 6 种子 = **36/36** 路径合法。
- **静态检查**：12 个 JS `node --check` 全通过；`main.js` ES5 约束扫描 0 命中。
- **合计 38 项断言全绿。**

**仍需真机人工确认**：

1. 先解锁小地图、再走到卷轴处 → 卷轴消失、toast 出现、把 F 面板里 `小地图解锁 ×N` 加 1；
2. 同场景下小地图**没有**被重新锁上（距离信息、指南针距离仍在）；
3. 未解锁时拾取卷轴 → 行为与改动前完全一致（保持锁定、距离隐藏、简单难度「地图在东侧」提示消失）；
4. 「最佳路径」在本局已解锁时也会绕去捡卷轴。

### 备注

- **库存语义**：已解锁后再拾取 → `mapUnlock` +1 留给**下一局**使用。本局再用会走
  `useItem('mapUnlock')` 的"本局已解锁，无需重复使用"分支，不消耗库存。
- **上一个判断的更正**：A 改造交付时，我在报告的"两点可能想顺手定的"第 2 条里写过这个场景，
  但当时判定"改动前就是如此，不是本次引入的"。该判断**错误** —— 这条路径正是 A 改造才打通的，
  已按本条目正式归因。
- **未修的同族小问题（不属本 bug，待定）**：HUD 的小地图按钮在"已拾取道具但尚未使用"时
  仍提示「尚未找到迷宫地图」。改成「已获得地图道具，按 F 使用」需要一个 `mapFound` 之外的判定
  （查一次 `MG.Shop.countOf('mapUnlock') > 0`），属于另一项改动，本轮未动。
