<h2 id="bug-045">BUG-045 · 开发者面板删掉 / 清空 / 导入存档后，钱包被内存缓存整份写回</h2>

- **发现日期**：2026-11-08
- **状态**：✅ 已修 / 2026-11-08
- **优先级**：P2
- **模块**：`js/shop.js` → `getWallet()` / `saveWallet()` / `invalidateCache()`；`js/dev.js` → 数据页 `del-key` / `wipe-all` / `import-all`

### 现象

在开发者面板「数据」页删掉 `maze3d.wallet.v1`、或「清空全部 `maze3d.*` 存档」、或「导入」覆盖钱包之后，
**任何一次**加币 / 购买 / 用道具都会拿内存里的旧钱包整份回写 —— 刚删掉或刚导入的钱包被静默覆盖回旧值；
期间 HUD 显示的余额也仍是旧值。表现是"删了又回来"。

### 根因

`MG.Shop` 把整份钱包缓存在模块级变量 `wallet`，只有**别的标签页**写盘时触发的 `storage` 事件会把它置空
（本标签自己的写入不会触发 `storage`）。`dev.js` 对签到模块已经处理了同类问题（`resetCheckinCache()`），
但没有对应的钱包失效动作，而 `MG.Shop` 也没有导出任何失效入口。

### 修复

- `js/shop.js` 新增并导出 `invalidateCache()`（把 `wallet` 置空，下次 `getWallet()` 重新读盘）；
- `js/dev.js` 新增 `resetShopCache()`，在「删除此项」（被删 key 是钱包键时）、「清空全部」、「导入」三处调用。

### 验证

Node 复现脚本对照：修复前 `getWallet()` 缓存后 `removeItem(钱包键)`，再 `addCoins(1)` → 磁盘上钱包键被写回旧余额；
修复后同一脚本磁盘键保持删除状态。`node --check` 通过。

<h2 id="bug-046">BUG-046 · `submitRecord()` 把非法用时兜底成 0 秒「最佳」，该难度记录从此永不更新</h2>

- **发现日期**：2026-11-08
- **状态**：✅ 已修 / 2026-11-08
- **优先级**：P2
- **模块**：`js/settings.js` → `submitRecord()`

### 现象

存档里一旦出现 `{time: 0}` 的最佳记录（非法入参写入、或手工改档 / 导入），
真实成绩（例如 25 秒）会返回 `isBest: false`，该难度的最佳记录**永久不再更新**。

### 根因

原实现 `if (!isFinite(Number(time))) time = 0;` 把"非法输入"变成了"理论最优值"；
而"更优"判定是 `time < cur.time - EPS`，`0 < 任何正数` 恒成立，于是 0 秒条目永远霸榜。
这与 `js/ranking.js` 的守卫（明确拒绝 `t <= 0` 直占榜首）**口径相反**，
也与 `loadRecords()` 注释承诺的"结构损坏可自愈"不符。

### 修复

- 入参非有限或 `<= 0`：直接返回 `{isBest:false, best: 现有或 null, all: rec}`，不再兜底成 0、不写盘；
- 存档中 `cur.time <= 0`（或步数非有限）视为无效，按空记录处理，让下一条真实成绩覆盖它；
- 合法数据行为不变（正常一局用时必 > 0），未改任何奖励数值。

### 验证

复算对照：修复前 `submitRecord('simple', NaN, 5)` → `{isBest:true,time:0}`，随后 `submitRecord('simple',25,60)` → `isBest:false`；
修复后前者 `isBest:false` 且不写盘，后者正常 `isBest:true`。`node --check` 通过。

<h2 id="bug-047">BUG-047 · 画质切换重建渲染器失败后，切回旧档会被跳过，档位永久不一致</h2>

- **发现日期**：2026-11-08
- **状态**：✅ 已修 / 2026-11-08
- **优先级**：P2
- **模块**：`js/main.js` → `onSettingChanged()` 的 `quality` 分支

### 现象

画质从「高」切「低」时若 `new THREE.WebGLRenderer()` 创建失败（显存紧张 / 浏览器拒绝第二个上下文），
`MazeView.applyQuality('low')` 仍执行（墙檐删除、粒子降到 60），但 `Game._appliedQuality` 因"重建失败不记账"仍是 `'high'`；
玩家再切回「高」→ 命中"档位没变"的跳过分支 → **MazeView 永久停在低档**，
渲染器/设置/墙檐/粒子/阴影接收四者长期不一致，且不会自愈。

### 根因

`applyQualityToSun()` / `mazeView.applyQuality()` / 墙体阴影同步这三项维护的是 **MazeView 自己的档位**，
却被放在"渲染器档位有没有变"（`_appliedQuality`）的守卫内部 —— 两个记账变量在重建失败时会分叉
（BUG-043 的"重建成功才记账"只解决了重试，没覆盖这个分叉）。

### 修复

把三项**移出** `if (Game._appliedQuality !== settings.quality)` 守卫，放到其后；
"要不要重建渲染器"与 toast 仍留在守卫内（避免重复提示）。三项都是幂等的：
`applyQuality` 同档首行早退，`applyQualityToSun` 只在阴影贴图尺寸真变化时才丢弃旧 map。

### 验证

`node --check` 通过；逻辑推演覆盖"重建成功/失败 × 切新档/切回旧档/恢复默认"四种组合；
`MazeView` 替身 harness 实测换档往返后金币与卷轴坐标不变、粒子数 60/140/220、低档不接收阴影、高档恢复。

<h2 id="bug-048">BUG-048 · 全屏 900ms 兜底在「进入成功后 900ms 内按 ESC 退出」时误报失败</h2>

- **发现日期**：2026-11-08
- **状态**：✅ 已修 / 2026-11-08
- **优先级**：P2
- **模块**：`js/ui.js` → `toggleFullscreen()` / `onFullscreenChange()`

### 现象

进入全屏成功后 900ms 内按 ESC（或 F11 / 系统手势）退出全屏，约 900ms 时会**多弹一条**「进入全屏失败，可先点一下页面再试，或按 F11」；
退出方向同理误报「退出全屏失败」。明明已经成功过。

### 根因

BUG-042② 的修法只加了 `fsToggleSeq` 序号作废，而序号只在**再点一次按钮**时自增
（`toggleFullscreen` 的唯一调用点是 HUD 按钮），ESC / F11 **不经过这个函数**；
同时成功路径（`onFullscreenChange`）只弹 toast、不置 `settled`。
于是 900ms 定时器仍执行 `if (当前状态 === 目标状态) 成功 else 失败`，此刻状态已不是全屏 → 误报。

### 修复

新增 `fsPendingWant` / `fsPendingReached` 两个状态位与 `markFullscreenPending()`：
在真正发起请求前登记目标状态，`fullscreenchange` 一旦确认"目标状态达成过"即置 `fsPendingReached`；
900ms 判定改为 `if (fsPendingReached || 当前状态 === 目标状态) 成功; else 失败`。
**从未达成（请求被静默忽略）仍如实报失败**，没有掩盖真失败。

### 验证

无头 DOM 桩（真实 900ms 计时）五场景，修复前后对照：
双击（先进后出）静默 ✓；进入成功后 ESC 退出 → 修复前误报失败、修复后只报「已退出全屏」✓；
退出后被 F11 重进 → 修复前误报、修复后静默 ✓；保持全屏静默 ✓；请求从未生效仍报失败 ✓。
界面层 70 条断言改动后仍 70/70。

<h2 id="bug-049">BUG-049 · 商店购买 / 消耗道具写盘失败被静默吞掉，仍提示「购买成功」</h2>

- **发现日期**：2026-11-08
- **状态**：✅ 已修 / 2026-11-08
- **优先级**：P2
- **模块**：`js/shop.js` → `buy()` / `spendCoins()` / `consumeItem()` / `addItem()`；`js/ui.js` → `doBuy()`；`js/main.js` → `consumeFailMsg()` / `useItem()`

### 现象

隐私模式、配额已满、存储被禁用时 `localStorage.setItem` 会抛异常，`safeSet()` 返回 `false`，
但原实现把这个返回值整个吞掉：玩家买了道具、扣了金币、界面弹「购买成功」，
**磁盘上什么都没变** —— 下次启动道具与余额一起回退，像是"凭空消失"。
用道具时同理：扣费失败也被当成成功。

### 根因

`buy` / `spendCoins` / `consumeItem` 都调用了 `saveWallet()` 却不看返回值；
`doBuy()` 只按 `res.ok` 提示，而 `buy()` 永远返回 `ok:true`（只要余额够）。

### 修复（用户拍板：如实提示并回滚）

- `buy()` 写盘失败 → 把内存里的金币与数量一起还原，返回 `{ok:false, reason:'save'}`；
- `consumeItem()` / `spendCoins()` 写盘失败 → 还原内存改动并返回 `false`；
- 新增 `takeSaveError()`（读取即清空）记录本次失败的操作名，**每个动作入口先清旧值**，
  保证调用方读到的一定是"自己这次"的结果；`addCoins()` 是唯一例外：通关奖励不回滚
  （回滚会吞掉玩家已获得的奖励），只是本局收益不落盘；
- `ui.js`：`reason === 'save'` 时提示「购买失败：本地存档无法写入（隐私模式或空间已满）」；
- `main.js`：扣道具失败时按原因区分「道具不足」与「本地存档无法写入，道具未使用」。

### 验证

Node 定向测试（18 条断言）：正常购买成功；写盘失败时 `reason='save'` 且金币与库存**双向回滚**；
`consumeItem`/`spendCoins` 失败回滚；恢复正常后功能不受影响；磁盘与内存一致；
陈旧标记不会污染下一次「数量不足」的判定。

### 备注

用户可见文案新增两处（商店失败提示、道具失败提示），均为**如实陈述**，不改任何成功路径文案。

<h2 id="bug-050">BUG-050 · 系统时间被调到未来后，签到被锁死且无自愈（连签与护符全部失效）</h2>

- **发现日期**：2026-11-08
- **状态**：✅ 已修 / 2026-11-08
- **优先级**：P2
- **模块**：`js/checkin.js` → `evaluate()` / `claim()` / `refreshBadge()` / `syncView()`

### 现象

系统时间被调到未来并签到、随后调回（或导入了未来日期的存档）后，`today < lastDay` 恒成立：
签到被判为 `reason='clock'` 拒绝，连签与护符全部失效，**且没有自愈路径**，
必须等真实日期追平 `lastDay`（若存档里是 `20991231`，近乎永久锁死）。
`parseDay()` 的注释本来就声称要防"永久锁死"，但只挡住了非法日历日期。

### 根因

设计上"只拦不罚"是对的（防改时间刷奖励），但缺少出口：异常计数 `anomaly` 每次点击只 +1 且不参与任何判定。

### 修复（用户拍板：连续异常 3 天后自愈）

- 新增常量 `CLOCK_RESET_DAYS = 3`（中文注释说明为什么是 3：1 天可能只是时区/夏令时抖动）；
- 新增字段 `anomalyFrom`（本轮首次异常观测日）与纯函数 `clockStrikes()`（今天算第 1 天）；
- 新增 `recordClockAnomaly()`：**同一天只写盘一次**（角标刷新 / 开面板这类高频入口不会写盘放大），
  并把计数从旧的"每次点击 +1"改为按天累加（连点几下不会被误判成"连续 3 天"）；
- 第 1~2 天维持 `clock` 拒绝（原行为不变）；第 3 天起返回
  `{canClaim:true, kind:'clock-reset', reason:'clock-reset', streak:1}`；
- 领取成功后清零异常计数与锚点，`lastDay=今天`、连签=1、累计天数 +1、最长连签保留、**护符不消耗**、发常规奖励；
- 记录点三处：`refreshBadge()`（boot / 回主菜单 / 跨天轮询）、`syncView()`、`claim()` 拦截分支；
- 玩家可见文案三处（均按 Lead 裁决成稿，数字由常量拼接）：
  自愈成功 toast 追加说明、自愈当天面板提示行、第 1~2 天拦截提示行补"连续 N 天后会自动重置"。

### 验证

`/tmp` 对照脚本 **29 条断言**（每条新开一次"页面会话"共享同一份 `localStorage`，并跑真实 `MG.Checkin.init()` 路径）：
D1/D2 仍拒绝且同日连点 ×3 不提前自愈；D3 自愈（连签 1 / 基准日改今天 / 异常清零 / 护符不消耗 / 金币入账 / `maxStreak` 保留）；
D4 回到 `normal` 且连签 +1；D5 连签 3；脏档 / 老档无锚点 / 非法锚点 / 断档 4 个边界。
签到既有回归脚本（跨月、跨年、闰年、夏令时 23h/25h 日、漏签档位、第 7/14/21/28 天保底）输出与修复前**逐行一致**；
概率 5 万次采样（大吉 1.114%、宝箱 8.000%、均值 7.6635）仍与 README 口径一致。

### 备注

<h3 id="bug-058">BUG-058 · 钱包数值溢出成 <code>Infinity</code> 后落盘成 <code>null</code>、下次启动静默清零 —— ✅ 已修</h3>

- **状态**：✅ 已修 / 2026-11-09（用户拍板："要设上限"）
- **优先级**：P3
- **模块**：`js/shop.js` → 新增 `MAX_WALLET_VALUE` / `clampValue()`，`normalizeWallet` / `addCoins` / `addItem` / `buy`

**根因**：`JSON.stringify(Infinity)` 得到 `null`，而 `normalizeWallet()` 把非有限数当损坏数据丢弃
→ 下次启动整个余额静默清零。原先只钳下界（`>= 0`），所以"余额 `1e308` + 奖励 `1e308` = `Infinity`"

**修复**：新增上限常量 `MAX_WALLET_VALUE = Number.MAX_SAFE_INTEGER`（`2^53-1 = 9007199254740991`）
与统一的 `clampValue()`（先把 `NaN` / `±Infinity` / 负数回落 0，再取整、再钳上界），
在四个入口全部套用：`normalizeWallet()`（含四个道具字段）、`addCoins()`、`addItem()`、
`buy()` 的计数类分支。上限取 `MAX_SAFE_INTEGER` 而不是自造数字：它是 JS 能精确表示的最大整数，
超出后连 `+1` 都不可靠；对迷宫游戏而言该量级（约 900 万亿金币）远超任何正常玩法与彩蛋奖励。

**验证**：定向测试 **14 条断言全过** —— 手改档 `1e308` / `1e300` 读盘被钳到上限且为有限数；
上限状态下 `addCoins(1e308)` 仍有限、落盘是上限而不是 `null`；
正常数值（100+25=125、道具 2+3=5、购买扣价 30）完全不受影响；
`null` / 负数 / 字符串等脏数据仍按原逻辑规范化；BUG-049 的回滚与陈旧标记测试同步复跑通过。
