<h2 id="bug-061">BUG-061 · 开发者面板里 <code>MG.Audio.portal()</code> 不发声，却仍提示「已播放」</h2>

- **发现日期**：2026-11-09
- **状态**：✅ 已修 / 2026-11-09
- **优先级**：P2（玩家可感知：贴近终点时的传送门环境提示音在手机上等于没有；且面板给出假消息）
- **模块**：`js/audio.js` → `portal()`（+ 新增 `diagnostics()`）；`js/dev.js` → `playAudioRaw()` / `renderAudio()`

### 现象

用户在「开发者选项 → 音频」页点 `MG.Audio.portal()`：**听不到任何声音**，
但面板底部仍显示「已播放 MG.Audio.portal()」。同一页其它音效按钮（click / step / coin / win …）都能听到。

### 复现

1. 打开游戏 → 长按商店按钮 → 两题验证 → 开发者选项 → 「音频」页；
2. 点 `MG.Audio.portal()`：无声音，状态栏仍报「已播放」；
3. 点同页 `MG.Audio.click()` / `MG.Audio.coin()`：正常出声（对照）。

### 根因分析

**两个独立问题，症状叠在一起。**

**① 这个音在手机小喇叭上根本发不出来（声音设计问题）**

`portal()` 原本是 `tone({ freq: 180, freq2: 240, type: 'sine', dur: 0.9, vol: 0.02~0.14 })` ——
一个 **180→240 Hz 的纯正弦**。把 11 个音效逐个离线渲染（见下"验证"）后对比频段能量：

| 音效 | 50–300 Hz | 300 Hz–1 kHz | 1 kHz–4 kHz | 300 Hz 以上 RMS |
|---|---|---|---|---|
| **portal（修复前）** | **100.0%** | **0.0%** | **0.0%** | 0.0209 |
| click | 0.4% | 99.2% | 0.3% | 0.0158 |
| coin | 6.9% | 18.2% | 75.0% | 0.0245 |
| win | 2.3% | 94.9% | 2.8% | 0.0807 |
| error（低频方波） | 93.9% | 5.6% | 0.6% | 0.0153 |

`portal` 是**唯一一个 300 Hz 以上零能量**的音效。`error` 虽然也低频（200→120 Hz），
但它是方波、带 3f/5f 奇次谐波，所以手机还能听见；而纯正弦只有基音，手机小喇叭在 300 Hz
以下几乎不发声 —— 于是"代码没抛错、波形也确实排进了音频图，但耳朵里是静音"。
这也解释了为什么游戏里"接近终点的低鸣"几乎没人注意到。

**② 开发者面板那句提示是无条件的（假消息）**

`playAudioRaw()` 原来是：调用 `fn()` 成功后**无条件** `setStatus('ok', '已播放 …')`。
而 `js/audio.js` 的 `tone()` 在音频上下文挂起/未解锁时会**直接放弃**本次发音
（为了不在解锁瞬间齐发，它刻意不排队），所以"已播放"这句话在那种情况下并不成立。
用户看到的正是这种"提示与事实不符"。

### 修复

**① 让这个音真的能被听见（保留"低频低鸣"的音色定位）**

```js
// 基音：低鸣本体（三角波自带 3f/5f 奇次谐波，比纯正弦多一层可闻泛音）
tone({ freq: 180, freq2: 240, type: 'triangle', dur: 0.9, vol: v });
// 八度泛音
tone({ freq: 360, freq2: 480, type: 'sine',   dur: 0.9, vol: Math.min(0.11, v * 0.8) });
// 十二度泛音：落在手机小喇叭能重放的频段
tone({ freq: 540, freq2: 720, type: 'sine',   dur: 0.9, vol: Math.min(0.07, v * 0.5) });
```

音量按距离衰减的原有语义（`intensity`）保持不变；未改动其它任何音效。

**② 让面板说实话**

- `js/audio.js` 新增只读导出 `diagnostics()` → `{ created, ctxState, volume }`（不会创建上下文）；
- `js/dev.js` 的 `playAudioRaw()` 改为**取调用前**的上下文状态：若不是 `running`，
  提示改为「已调用 … 但音频上下文是「suspended」，本次不会出声：先点一下页面任意处再试」。
  用调用前的状态而不是调用后的，是因为 `tone()` 挂起时会顺手 `resume()`，
  真实浏览器里状态可能立刻就不是 `suspended` 了，只看调用后会把这"其实没出声"的一次误判成成功。
- 「音频」页新增：真实的 `AudioContext` 状态、实际总增益、以及状态异常时的醒目提示；
  `portal` 按钮补一个说明标签「0.9s 低频低鸣（贴近终点才明显；已加泛音，手机喇叭可闻）」。
  面板打开期间 `MG.Audio` 的方法会被整体替换成空函数来实现静音，所以读诊断信息要走**静音前的备份**。

### 验证

1. **离线渲染 + 频谱体检**（`harness/audio-render.js`，把 `audio.js` 真跑一遍并渲染成 WAV）：

   | 指标 | 修复前 | 修复后 |
   |---|---|---|
   | 300 Hz 以上 RMS | 0.0209 | **0.0416**（×2） |
   | 300 Hz 以上峰值 | 0.0823 | 0.1274 |
   | 300 Hz–1 kHz 能量占比 | **0.0%** | **27.5%** |
   | 总峰值 | 0.084 | 0.139（与 `click` 0.132 同级，低于 `win` 0.377） |
   | 振荡器数 | 1 | 3 |

   可试听对比：`harness/audio/portal-before.wav` / `portal-after.wav` /（对照）`sfx-error.wav`。

2. **端到端（真开开发者面板点按钮）**：`13 条断言全过` ——
   面板打开 → 音频页 → `portal` 按钮真的排了 **3 个振荡器**且提示「已播放」；
   `click` 仍只排 1 个（未误伤其它音效）；
   把上下文置 `suspended`（并用**异步** `resume()` 模拟真实浏览器）后：
   `portal` **一个振荡器都没排**（确实没出声）且提示如实说明"本次不会出声"；
   恢复 `running` 后其它音效提示正常；音频页状态卡显示真实 `ctxState` 与解锁指引。

3. **回归**：`node --check` 14/14；ES5 扫描 0 命中；无头冒烟 **9/9 PASS**；
   界面层无头断言 **70/70**；`click`/`coin`/`win`/`error` 等音效的参数与频段分布**未变**。

### 备注

- 真机最终仍以耳朵为准：如果你觉得低鸣还是偏轻 / 偏亮，直接说，我调 `portal()` 里那三个
  泛音的权重即可（基音 `vol: v`、八度 `v*0.8`、十二度 `v*0.5`）。
- 这条不属于"设计取舍被误报"：波形确实存在、代码也没抛错，但**用户听不到**且**面板给了假消息**，
  两半都是实打实的缺陷。

<h2 id="bug-062">BUG-062 · 电脑 / 笔记本 / 平板上的小地图固定偏小（168px 上限，任何难度都小）</h2>

- **发现日期**：2026-11-09
- **状态**：✅ 已修 / 2026-11-09
- **优先级**：**P0**（用户点名：直接影响游戏界面 UI 的可用性）
- **模块**：`css/style.css`（小地图尺寸口径）、`index.html`（设置行）、`js/settings.js`、
  `js/ui.js`、`js/main.js`

### 现象

桌面 / 笔记本 / 平板上小地图**固定很小**，而且**任何难度都一样小**（与迷宫大小无关）：

| 设备 / 视口 | 修复前 | 占屏宽 |
|---|---|---|
| 平板竖屏 768×1024 | 168px | 22% |
| 笔记本 1366×768 | 168px | 12.3% |
| 笔记本 1920×1080 | 168px | **8.7%** |
| 桌面 2560×1440 | 168px | **6.6%** |

### 复现

1. 用桌面浏览器（窗口高度 >720px，几乎一切桌面/平板）打开游戏，选任意难度开局；
2. 拾取「地图卷轴」并在道具面板里解锁小地图；
3. 观察右上角小地图 —— 固定 168px，屏幕越大显得越小；手机上是正常的 34vw 比例。

### 根因分析

`.minimap-wrap { width: min(34vw, 168px) }`（横屏紧凑档为 `min(26vh, 132px)`）。
`min(34vw, 168px)` 里的 **168px 是"手机上限"**，但没有任何媒体查询把它限制在手机上：

- 视口一高过 720px，`34vw` 就远超 168px（1080p 上是 653px），于是**永远取上限 168px**；
- 横屏紧凑布局的门槛是 `(orientation: landscape) and (max-height: 720px)`，
  1366×768 的笔记本**不命中**它，走默认分支 —— 然后同样被 168px 吃掉。

结果就是"尺寸与视口脱钩"：手机（34% 屏宽）正常，桌面（8.7%）小得看不清。

### 修复

**① 尺寸口径：固定像素 → 视口比例（CSS 变量 + 档位覆盖）**

| 作用域 | 公式 |
|---|---|
| `:root`（自动・默认） | `clamp(120px, min(34vw, 34vh), 320px)` |
| `:root`（自动・横屏矮屏） | `clamp(96px, min(30vw, 30vh), 320px)` |
| `body[data-minimap-size="small"]` | `clamp(96px, 20vmin, 180px)` |
| `body[data-minimap-size="medium"]` | `clamp(120px, 26vmin, 260px)` |
| `body[data-minimap-size="large"]` | `clamp(140px, 34vmin, 360px)` |

`.minimap-wrap` 改为 `width/height: var(--minimap-size)`。
两条实现要点：**横屏档改 `:root` 上的变量而不是改 `.minimap-wrap` 本身**
（元素级声明会盖掉 `body[data-…]` 的手动档位，玩家选了大小就该说了算）；
**「自动」档不设 body 属性**，直接走自适应公式。每档都保留一条纯 px 兜底值给老内核。

**② 设置面板可调 + 界面提示**（用户要求："先自己自动调，玩家不满意可以随时进设置调，
所以肯定要有点提示在里面"）：

- 新增设置行「小地图大小」：`自动（按屏幕比例） / 小 / 中 / 大`，默认自动；
- 行内**徽标**实时显示当前档位与实际像素（如 `自动 · 261px`），让玩家知道现在多大、能调；
- 行下补一句说明：「电脑 / 平板上的小地图会按屏幕比例自动放大；觉得太大或太小，随时改这里。」

**③ 接线**：`js/settings.js` 加默认值 `minimapSize: 'auto'` 与枚举校验（非法值/旧档保持原值，
老档缺字段回落 auto）；`js/ui.js` 新增 `applyMinimapSizeToBody()` / `refreshMinimapSize()` /
徽标更新（`refreshMinimapSize()` 是**唯一入口**，避免"徽标变了但尺寸没变"的半生效状态）；
`js/main.js` 在 `onSettingChanged` 里对 `minimapSize` 立刻生效 —— 重新测量容器并按 dpr 重设画布
分辨率（复用 BUG-027 的既有链路，隐藏状态下转为待处理，由下一次 `drawMinimap` 兜底）。

### 验证

1. **公式求值**（脚本直接读 `css/style.css` 的真实声明并按设备视口求值，不是抄一遍公式）：

   | 设备 | 视口 | 修复前 | 修复后·自动 | 占屏宽 | 小 | 中 | 大 |
   |---|---|---|---|---|---|---|---|
   | 手机竖屏 | 390×844 | 132.6px | **132.6px（不变）** | 34.0% | 96 | 120 | 140 |
   | 手机横屏 | 844×390 | 101.4px | 117.0px | 13.9% | 96 | 120 | 140 |
   | 平板竖屏 | 768×1024 | 168.0px | **261.1px** | 34.0% | 154 | 200 | 261 |
   | 平板横屏 | 1024×768 | 168.0px | **261.1px** | 25.5% | 154 | 200 | 261 |
   | 笔记本 1366×768 | 1366×768 | 168.0px | **261.1px** | 19.1% | 154 | 200 | 261 |
   | 笔记本 1440×900 | 1440×900 | 168.0px | **306.0px** | 21.3% | 180 | 234 | 306 |
   | 桌面 1920×1080 | 1920×1080 | 168.0px | **320.0px** | 16.7% | 180 | 260 | 360 |
   | 桌面 2560×1440 | 2560×1440 | 168.0px | **320.0px** | 12.5% | 180 | 260 | 360 |

   断言全过：手机竖屏保持原尺寸、手机横屏仍走横屏公式、平板/笔记本/桌面明显变大、大屏不失控（≤320px）。

2. **端到端（真启动游戏、真的改下拉、真的点重置）24 条断言全过**：
   4 个档位与默认 `auto`；auto 不设 body 属性；选「大」→ 设置生效 + body 属性 + 徽标 + 落盘
   `maze3d.settings.v1`；切回 auto 清属性；非法值（`'huge'` / 数字）被校验挡掉；
   点「重置设置」→ 回 auto + 清属性 + 下拉回填；`refreshMinimapSize()` 在小地图隐藏时不抛错；
   老存档（无 `minimapSize` 字段）回落 auto 且其它字段不受影响。

3. **回归**：`node --check` 14/14；ES5 扫描 0 命中；无头冒烟 **9/9 PASS**；
   界面层无头断言 **70/70**；新增元素 id 在 `index.html` 中存在；
   BUG-027（分辨率随窗口更新）走的是同一条 `resizeMinimap()` 链路，未见回归。

### 备注

- **手机端尺寸一字未改**（390×844 仍是 132.6px），改动只影响"被 168px 上限压住"的那些设备。
- 「点击地图 → 最大化 / 非模态不互顶」按用户 2026-11-09 的决定**暂不实现**，
  设计见工作区文档 `../新难度-地图可读性设计.md`（方案 M2/M3），做新难度时再落地。
- 真机验收项：桌面/笔记本/平板各开一局，确认小地图变大且不挡视线、不遮 HUD 与指南针；
  在设置里切换小/中/大能立刻看出差别；手机端与修复前观感一致。

<h2 id="bug-063">BUG-063 · 归档文件没有目录，无法直接跳转到对应缺陷</h2>

- **发现日期**：2026-11-09
- **状态**：✅ 已修 / 2026-11-09
- **优先级**：P3（文档 / 流程格式）
- **模块**：`BUG/*.md`（归档文件）、`BUG/BUG.md`（模板与约定）、`_模板.md`、`README.md`

### 现象

`BUG/` 下的归档文件格式不统一：

- `BUG(2026.11.07).md`（1369 行 / 15 条）、`BUG(2026.11.08).md`（545 行 / 16 条）、
  `BUG(2026.11.09).md` —— **完全没有目录**；
- `BUG(2026.10.25).md` —— 有目录，但 16 条链接用的是**自动锚点**形式
  （`#bug-001--指南针方向反转`，由标题临时生成），标点一变就点不动；
- 只有 `BUG(2026.10.30 / 10.31 / 11.01).md` 是"**显式 `id` + 目录链接**"的正确形态。

结果：查一条历史缺陷只能 `Ctrl+F` 或手改 URL —— 这正是用户反馈的"设计上的 bug"。

### 根因分析

归档格式只存在于口口相传里，**没有落到模板中**：`BUG.md` 的记录模板只规定"单条 BUG 怎么写"，
没有规定"归档文件长什么样"；也没有锚点写法要求，于是"自动锚点"与"显式 id"两种写法混用至今。

### 修复

1. **补齐目录 + 统一锚点**：7 个归档文件全部具备 `## 目录`；每条 BUG 的标题统一为
   显式锚点 `<h2 id="bug-0xx">…</h2>`；非条目章节（复查方式 / 后续补修 / 改动文件汇总 /
   验证汇总 / 口径订正 / 第二批）也给显式 id，目录的「其他章节」一节指向它们；
   `BUG(2026.10.25).md` 那 16 条失效链接一并改为 `#bug-0xx`。
   **只加目录、补 id、修链接 —— 正文一字未改**（历史结论仍按"只增不改"保留）。
2. **写进模板（关键）**：`BUG/BUG.md` 新增「归档文件模板（必须带目录）」一节，
   给出骨架 + **新增归档文件时必须满足的 3 条** + 一条可复制的自查命令；
   顶部约定与页脚「归档约定」都点明该要求；`_模板.md`（CHANGELOG 模板）与 `README.md`
   各加一句指向说明。

### 验证

1. **自查命令**（已写进 `BUG.md`，可直接复制执行）：7 个归档文件输出**全部** `断链： 无`；
2. **逐文件核对**：每个文件的目录条目数 == 该文件 BUG 条目标题数
   （`16 / 5 / 1 / 7 / 15 / 16 / 2`），无漏项、无重复编号；
3. **抽查渲染**：目录链接形如 `- [BUG-062 · …](#bug-062)`，对应 `<h2 id="bug-062">` 存在，
   GitHub 与本地 Markdown 预览里均可直接跳转。

### 备注

"只增不改"针对的是**历史结论与证据**；本次只增加索引、补齐锚点属性、修正失效链接，
不改写任何一条结论。若日后确需改动历史归档正文，仍按老规矩另起条目说明。
