<h2 id="bug-064">BUG-064 · 对局中经开发者面板跳转的商店/排行榜/成就/签到，点「返回」会落到主菜单</h2>

- **发现日期**：2026-11-13
- **状态**：✅ 已修 / 2026-11-13
- **优先级**：P3（仅开发者面板可达，不影响正常玩家路径）
- **模块**：`js/ui.js` → 排行榜返回 / 成就返回 / 商店返回 / `isOverlayOpen()`；
  `js/checkin.js` → `closePanel()`；`js/dev.js` → `doGoto()`；
  `js/main.js` → `Game.input.onPause`（ESC / P 优先级链）
- **用户原话（2026-11-13）**：
  > 这个 bug 是必须开启开发者选项之后才能实现的。首先，解锁开发者选项。第二步，随便进入什么难度。
  > 然后进入开发者选项，随便选一个界面 UI 进入，除了主菜单以外，如果选择签到，点击返回会回到主菜单，
  > 但是背景仍然是当前对局的背景，只不过被暂停了而已，不过，回到设置仍然是暂停菜单。
  > 我觉得除了里面的主菜单按钮以外，所有在对局中点到的按钮，点击返回永远都是暂停菜单。

### 现象 / 根因

对局中（`Game.state === 'paused'`）从开发者面板「环境 → 快速跳转」进入

| 跳转目标 | 返回落点（修复前） |
|---|---|
| 商店 / 排行榜 / 成就 / 签到 | ❌ 主菜单（`showMainMenu()`） |
| 设置 | ✅ 暂停菜单（BUG-056 已修的那一条） |

四条错误路径的返回处理各自写死了 `showMainMenu()`（下列行号为**修复前**的 `5ec7ebf`）：

- `js/ui.js:644`（排行榜 `#btn-ranking-back`）→ `hide('ranking-screen'); showMainMenu();`
- `js/ui.js:670`（成就 `#btn-achievements-back`）→ `hide('achievement-screen'); showMainMenu();`
- `js/ui.js:780`（商店 `#btn-shop-back`）→ `hide('shop-screen'); showMainMenu();`
- `js/checkin.js:824`（`closePanel()`）→ `MG.UI.showMainMenu();`

而这四个界面既可以从主菜单进（正常玩家路径），也可以在对局暂停中经
`js/dev.js:1334 doGoto()` 进 —— `doGoto()` 只对 `settings` 传了来源
（`wasPaused`，那是 BUG-056 的补丁），其余四条**没有传来源**，于是返回时一律落到主菜单。

后果：主菜单盖在一局 `state === 'paused'` 的**僵尸对局**上 ——
关卡没有释放（`Game.mazeView` 还在）、HUD 与暂停菜单都不显示，所以背景仍是那一局的画面，
看起来就是"回了主菜单，但背景是暂停的对局"。属导航不一致，不是状态损坏。

**与 BUG-056 的关系**：`BUG(2026.11.08).md` 的 BUG-056 记录的就是同一族缺陷
（「快速跳转 → 设置」落到主菜单），当时只在 `doGoto()` 里为"设置"这一条补了来源参数，
其余四条没有一并处理 —— 本条是它的**同族遗留**。这也是本次不再逐条传来源、
改为在 UI 层做**统一判定**的原因：逐条传参正是上一轮漏掉四条的原因。

### 复现（用户路径，逐步可重复）

1. 主菜单长按「商店」约 0.48 秒 → 依次答对两题（`deepseek` / `AdroitHare8579`）解锁开发者选项；
2. 随便选一档难度开始游戏，进入 `playing`，再暂停（HUD 暂停键或 `P`）；
3. 点界面上补挂的开发者免密入口打开面板 → 切到「环境」页签 → 点「快速跳转」里的
   商店 / 排行榜 / 成就 / 签到；
4. 在该界面点「返回」（`#btn-shop-back` / `#btn-ranking-back` / `#btn-achievements-back` /
   `#btn-checkin-close`）；
5. **修复前**：落到主菜单，`Game.state` 仍是 `'paused'`、`Game.mazeView` 仍在，
   背景是那一局的画面；**修复后**：回到暂停菜单，`state === 'paused'`，可以点「继续游戏」。

同一条复现路径的 ESC / P 变体（第 4 步改成按 ESC 或 P）见下一节。

### 复查中发现的同族第二处：ESC / P 键会**把对局恢复起来**，而覆盖层不关

修完返回落点后做全量路径审计时发现：`js/main.js` 的 `Game.input.onPause`（ESC / P）优先级链
只给 签到 / 道具面板 / 设置 / 回放 写了分支，**商店 / 排行榜 / 成就 三个覆盖层没有分支**，
于是落到链尾的 `else if (Game.state === 'paused') resumeGame();`：

1. 暂停局 → 开发者面板 → 快速跳转 → 商店，按 **ESC**；
2. `resumeGame()` 把 `state` 变回 `'playing'`、隐藏暂停菜单、显示 HUD，**但商店界面仍然开着**
   （与 BUG-016 同一类"面板背后游戏继续跑"的问题）；
3. 此时玩家点商店的「返回」：`backFromOverlay()` 现读 `Game.state === 'playing'` →
   落到**主菜单**；对局就此在主菜单背后继续跑，`loopBody()` 的 `playing` 分支照常推进，
   **走到终点还会后台触发 `onVictory()`，凭空写入排行榜 / 回放 / 钱包** ——
   这正是 `js/dev.js` 里"打开面板前必须先暂停"那段注释（BUG-036）警告过的情形。

这条也说明：**"现算 `Game.state`"的写法只有在"面板开着时没人能改状态"时成立**，
所以 ESC / P 必须与鼠标点「返回」走同一条路径，否则现算反而会算出错的落点。

### 同族第三处（**未修**，已登记为 BUG-065 待用户拍板）

对局**已通关**（`state === 'win'`、胜利界面还开着）时，胜利界面上也有开发者免密入口，
从那里进覆盖层再返回同样会落到主菜单，留下 `state === 'win'` + 关卡未释放的僵尸。
涉及 `js/ui.js` 的 `backFromOverlay()` / `closeSettings()`、`js/dev.js` 的 `close()`
与「快速跳转 → 设置」共三处。**未修的原因**：用户 2026-11-13 给的口径只覆盖"对局中"
（暂停态），"已通关后返回该回胜利界面还是直接回主菜单"属于产品口径，需用户先拍板。
证据与建议见 `BUG/BUG.md` 的「待确认项 · BUG-065」。

### 修复

1. **`js/ui.js` 新增统一的「覆盖层返回」判定**（导出 `MG.UI.backFromOverlay`）：

   ```js
   function isPausedGame() { return !!(MG.game && MG.game.state === 'paused'); }
   function backFromOverlay() {
     if (isPausedGame()) { hideAllScreens(); show('hud'); show('pause-menu'); return; }
     showMainMenu();
   }
   ```

   判定在"点返回的那一刻"用 `Game.state` 现算，**不记录来源**：既不会像逐条传参那样漏路径，
   也不会引入"来源记错"的第二个缺陷。代价是必须保证"面板开着时没人能改状态" ——
   这正是下面第 5 条（ESC / P）一并修掉的原因。
2. **商店 / 排行榜 / 成就三条返回**（`js/ui.js`）改调 `backFromOverlay()`，
   删掉各自的 `hide('xxx-screen')`（`backFromOverlay()` 两个分支都先 `hideAllScreens()`）。
3. **`js/checkin.js` 的 `closePanel()`** 改为优先调 `MG.UI.backFromOverlay()`；
   取不到时按 `showMainMenu()` → `hide('checkin-screen')` 逐级兜底，保持可降级。
4. **`js/dev.js` 的 `doGoto('menu')`**：存在活关卡（`MG.Game.mazeView`）时改走引擎的
   `MG.UI.pauseCallbacks.onMenu()`（= `main.js` 的 `backToMenu()`），
   释放关卡并把 `state` 归 `menu`、清掉关卡遗留的雾与背景色 ——
   与暂停菜单里的「返回主菜单」按钮走完全同一条路径。
   修复前这一跳同样会留下僵尸对局（背景仍是那一局），属同族问题一并处理。
5. **ESC / P 与鼠标点「返回」走同一条路径**（同批复查发现的第二处）：
   - `js/ui.js` 新增并导出 `isOverlayOpen()` —— 商店 / 排行榜 / 成就 三个界面是否正开着；
     彩蛋验证弹窗可见时返回 `false`，把那一按 ESC 让给弹窗自己（逐层关闭，与签到 / 设置手感一致）。
   - `js/main.js` 的 `Game.input.onPause` 在设置分支之后新增
     `if (MG.UI.isOverlayOpen()) { MG.UI.backFromOverlay(); return; }` ——
     ESC / P 在覆盖层里改为"关面板 + 回到进来时那一层"，不再掉进 `resumeGame()`
     把对局恢复成 `playing`、把成绩暴露给后台结算。
6. **不改** `showMainMenu()` 自身的语义，**不动**暂停菜单 / 胜利界面的既有按钮，
   也**不动** `closeSettings()` 的 `pause-menu` / `hud` 两个正确分支。

### 验证

见文末「验证汇总」。核心口径：四条路径 × 两种来源（暂停局 / 主菜单）返回落点正确；
暂停局返回后 `state` 仍为 `'paused'`、`#pause-menu` 与 `#hud` 可见、其余界面全隐藏；
从主菜单进入时行为与修复前完全一致（回主菜单）。

### 备注

- 这个缺陷**只有开发者面板可达**（正常玩家从主菜单进这四个界面，返回主菜单本来就是对的），
  所以定 P3；但"面板背后留一局活着的对局"是会被后续操作放大的隐患 ——
  复查时果然找到了 ESC / P 这条会**把对局恢复起来并在后台结算**的路径（见上），
  因此按既有的"面板导航必须自洽"标准一并修掉。
- 修复刻意**不做**"记住来源"式的状态变量：`settingsFrom` 那种写法在 BUG-056 里就已经
  证明容易漏路径（新增入口忘记传参就静默退化）。统一现算 `Game.state` 只依赖引擎的单一事实源；
  代价是必须保证"面板开着时没人能改状态"，这就是第 5 条一并修 ESC / P 的原因。
