<h2 id="bug-069">BUG-069 · 设置里调节「小地图大小」后，徽标数值不实时刷新</h2>

- **发现日期**：2026-11-15（用户反馈）
- **状态**：✅ 已修 / 2026-11-15
- **优先级**：P3（只影响设置面板里的提示数值，功能本身是即时生效的）
- **模块**：`js/ui.js` → `updateMinimapSizeBadge()` / `resizeMinimap()` / `refreshMinimapSize()`；
  新增 `readMinimapSizePx()`
- **用户原话**：> 设置里调节地图的大小，它不会实时刷新数值，必须退出设置之后再打开才能刷新

### 现象

在设置面板里把「小地图大小」从"自动"切到"大"（或反过来），行内徽标（`#set-minimap-size-state`）
**只更新档位文字**，后面的像素值要么保持上一个档位的旧数字、要么空白；
退出设置回到对局再进来，才显示正确数值。

### 根因

设置面板打开时会 `MG.UI.hide('hud')`（见 `showSettings`），小地图容器随之不可见 ——
`resizeMinimap()` 量到 `clientWidth === 0`，拿不到"该档位对应的实际像素"，
`updateMinimapSizeBadge()` 只能更新档位文字；像素值要等回到对局里
（`drawMinimap()` 里那次"补测" `minimapResizePending`）才刷新。

### 修复

新增 `readMinimapSizePx()`，**四级回退**，越靠前越准：

1. 容器可见 → 直接量 `clientWidth`（常规路径，对局里就是这条）；
2. 读 CSS 变量 **`--minimap-size`**（`getComputedStyle(document.body).getPropertyValue(...)`）——
   它是 BUG-062 起就存在的**唯一事实源**，body 可见时随时可读，**不受小地图容器显隐影响**；
   纯 px 值直接可用；
3. 若该变量是 `clamp()/min()/vmin` 这类表达式（不是纯 px），挂一个不可见的**探针元素**
   （`width: var(--minimap-size)`），**让浏览器自己求值**后再量它的宽度；
4. 四条都拿不到 → 徽标**只显示档位、不显示数字**（宁可不显示，也不显示陈旧/假数字）。

**为什么不在 JS 里再算一份 clamp 公式**：那会在 CSS 与 JS 两处各存一份口径，
将来改尺寸只改一处就会静默漂移（本项目 BUG-046/051 就是"读写两侧口径不一致"的同族问题），
所以宁可让浏览器求值。

### 验证

- 修复前基线复现："大 · **168px**"（旧档位残留值）；修复后："大 · **261px**"（当前档位真实值）。
- 两条路径都实测：**纯 px 变量**（老内核兜底档）与 **clamp 表达式**（现代档位）。
- 独立验证（见文末「验证汇总」）覆盖"容器隐藏时切档位 → 徽标立即变为正确值且不是陈旧数字"。

### 备注

同类问题以后还会遇到：**"面板打开 → 容器被隐藏 → 量不到尺寸"**。
统一思路是"去读 CSS 变量/让浏览器求值"，而不是在 JS 里复制尺寸公式。
另注：`updateMinimapSizeBadge()` 的调用链（`applyMinimapSizeToBody()` / `refreshMinimapSize()`）
一字未动，只是它现在能拿到正确数值了。
