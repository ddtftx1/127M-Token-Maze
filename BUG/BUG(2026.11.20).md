<h2 id="bug-070">BUG-070 · 困难档「最佳路径」规划阶段冻结 17~30 秒</h2>

- **发现日期**：2026-11-20（来自 `检查结果说明(2026.11.20).md` 的「疑似-1」）
- **状态**：✅ 已修 / 2026-11-20
- **优先级**：P1
- **模块**：`js/pathfinding.js` → `buildGreedyCollectPath()`、`simplify()`、新增 `tracePathOnField()`；
  调用方 `js/main.js` → `buildBestPath()`（未改，只受益）
- **现象**：困难档（121×121）在道具面板点「最佳路径」后，页面**整页冻结十几到三十秒**才进入自动行走；
  期间无任何提示、无法操作。简单档 27ms、中等档 72ms，玩家感知不到。只影响「最佳路径」这个付费道具，
  「最快路径」（距离场梯度下降）不受影响。
- **复现**：困难档开局 → 打开道具面板 → 使用「最佳路径」→ 观察主线程卡死时长。
  无头复现：`cd harness && node bug070-073-verify.js --only=A --maze=<修复前副本>`。
- **根因分析**：两处叠加，都是"困难档从 31×31 变成 121×121 之后没被重新跑过"的漏测：
  1. `buildGreedyCollectPath()` 每一轮对**剩余的全部目标**各跑一次**全图 A\***：
     61 个目标 → 61+60+…+1 = **1891 次**全图 A\*（实测修复前 6.7~6.8 秒）。
     不变量注释里写的"约 66 次"停留在旧困难档（31×31、约 11 个目标）口径，已漂移。
  2. `simplify()` 外层对每个点 `i` 都从**路径末尾**往回线性回退，每退一步跑一次 Bresenham
     视线检测；蛇形迷宫里"从 i 能直线看到的最远点"通常就在 `i+2`/`i+3`，
     等于每个点都把整条剩余路径扫一遍 → 困难档（约 4500~4900 点）最坏 O(n²·L) 次视线检测
     （实测修复前 10.8~13.5 秒）。
- **修复**：
  1. **收集阶段改"一轮一次 BFS 距离场 + 回溯"**：每轮只跑一次 `bfsDistMap()`（O(V)），
     同时完成"挑最近目标"（BFS 步数就是真实最短步数，选出来的目标与旧实现**逐个一致**，
     并列时同样取 `remaining` 里靠前的）与"在距离场上回溯最短路径"（新增 `tracePathOnField()`）。
     1891 次 A\* → 61 次 BFS。
  2. **简化改前向扫描**：从 `i+2` 起逐格尝试"跳过中间点后是否仍直线可达"，**首次失败即停**，
     取失败前一格作为下一途经点。每条被采用的段都经 `lineOfSight()` 逐格校验；
     `protectedSet` 的保护格（金币 / 卷轴 / 终点）仍被强制保留为途经点（扩张时一旦要跳过保护格就停）。
     复杂度从 O(n²·L) 降到 O(Σ可见跨度·L)。
- **验证**（修复前副本 vs 修复后，同一脚本 `harness/bug070-073-verify.js`）：

  | 项 | 修复前 | 修复后 |
  |---|---|---|
  | 困难档单次规划合计（seed 1） | **17 519 ms** | **101 ms** |
  | 困难档单次规划合计（seed 2） | **20 265 ms** | **113 ms** |
  | 其中 收集路径 | 6 763 / 6 813 ms | 91 / 106 ms |
  | 其中 简化 | 10 756 / 13 452 ms | 10 / 7 ms |
  | 同一输入下简化结果 | 1 437 点 | **1 437 点（逐点一致）** |
  | 中等档合计 | 20 ms | 7 ms |
  | 正确性 | — | 61/61 目标被经过；简化后每段不穿墙；保护格 0 丢失；同输入可复现 |

  另：`harness/bug070-073-verify.js` A 组 **23 PASS / 0 FAIL**（两组困难 + 一组中等）。
  困难档-简化耗时对照（同一份 4 571 点输入）：**旧 10 750ms → 新 9ms**，输出同为 1 437 点。
- **备注**：多条等长最短路时，"距离场回溯"与旧 A\* 选的具体格子可能不同（两者都是最短路），
  属于同一条最佳路径的等价解；目标选择顺序与总长度不变，不影响成就「自力更生」、
  也不改存档/回放格式。`aStar()` 仍是导出函数（`findWorldPath` 的 field 回退与尾段拼接在用），
  没有变成废码。

<h2 id="bug-071">BUG-071 · 性能模式级联改画质/阴影后，设置面板不跟着变</h2>

- **发现日期**：2026-11-20（来自 `检查结果说明(2026.11.20).md` 的「疑似-2」）
- **状态**：✅ 已修 / 2026-11-20
- **优先级**：P2
- **模块**：`js/ui.js` → `MG.UI` 导出表；调用方 `js/main.js` → `onSettingChanged()`
- **现象**：在设置面板里打开「性能模式（激进）」后，设置**实际值**已被级联改成
  `quality = low`、`shadows = false`，但面板上的画质下拉仍显示「中/高」、阴影开关仍是「开」；
  玩家对着面板拨开关，看到的是不一致的状态。
- **复现**：主菜单 → 设置 → 先把画质调「高」、阴影打开 → 拨「性能模式」→ 观察画质下拉与阴影开关
  **不变化**。无头复现：`node bug070-073-verify.js --only=B --maze=<修复前副本>`（B 组 2 FAIL）。
- **根因分析**：`js/ui.js` 里 `syncSettingsUI()` 有定义，并在 `init()` / `showSettings()` /
  「恢复默认」三处内部调用，但**没有写进文件末尾的 `MG.UI = { ... }` 导出对象**。
  而 `js/main.js` 的调用写法是 `if (MG.UI && MG.UI.syncSettingsUI) MG.UI.syncSettingsUI();` ——
  守卫取到 `undefined` 直接短路：**不报错、什么也不发生**。
  `settings.js` 里性能模式的注释、`ui.js` 设置面板的注释、`CHANGELOG.md`（2026-11-15.2）
  都明确承诺了"面板必须同步显示"，属于文档有、代码没接上。
- **修复**：在 `MG.UI` 导出表里补一行 `syncSettingsUI: syncSettingsUI`（带注释说明为什么必须导出）。
- **验证**：B 组 6 PASS / 0 FAIL：
  面板先显示 high/开 → 开性能模式 → 设置值 low/关 **且 DOM 下拉=low、阴影=false** →
  关性能模式 → 恢复 high/开 **且 DOM 同步恢复**。修复前副本同一脚本：DOM 两项 FAIL（实际 high / true）。
- **备注**：这一条**不改变**性能模式的级联/备份/可逆逻辑（那部分 2026-11-15.2 已验证正常），
  只补"把生效值回写到控件"。开发者面板里通过 `toggle-setting` 改画质也走同一条 `set()` 广播，
  所以同样被修好。

<h2 id="bug-072">BUG-072 · 退出回放后画布停在回放第三人称视角</h2>

- **发现日期**：2026-11-20（来自 `检查结果说明(2026.11.20).md` 的「疑似-3」）
- **状态**：✅ 已修 / 2026-11-20
- **优先级**：P2
- **模块**：`js/main.js` → `exitReplay()`
- **现象**：通关 → 点「看回放」→ 退出回放后，胜利界面**背后那张 3D 画面**还是回放时的
  第三人称视角（相机在幽灵身后约 5 米、高 4.5 米），而不是玩家通关时的第一人称视角。
  是否明显取决于胜利界面毛玻璃强度，但底层逻辑确实是"改了画面却没重画"。
- **复现**：通关 → 「看回放」→ 播放一会 → 退出 → 看胜利界面背后的画面。
  无头复现：`node bug070-073-verify.js --only=C --maze=<修复前副本>`（C 组 1 FAIL：退出后 0 次渲染）。
- **根因分析**：2026-11-14 的 BUG-066 把菜单/暂停/胜利态改成了**脏标记按需渲染**
  （`isSceneCovered()` 把 `menu / paused / win` 判为"被全屏层盖住、可跳过渲染"），并立下规矩：
  "任何在覆盖状态下改变 3D 画面的路径都必须 `markSceneDirty()`"。当时列了 5 条
  （回菜单 / resize / 设置变更 / 进入暂停 / 通关），`exitReplay()` 是漏掉的**第 6 条**：
  它把 state 改成 `win` 后调用 `player.syncCamera()` 与 `applyFog()`，却没置脏；
  而回放期间每帧都渲染，`_sceneDirty` 一路是 `false` → 这两处改动一帧都没画出来。
- **修复**：在 `exitReplay()` 末尾（相机与雾都还原之后）补 `markSceneDirty()`，并写清"为什么是第 6 条"。
- **验证**：C 组 8 PASS / 0 FAIL：
  回放态每帧渲染（3 帧 3 次）→ `_sceneDirty === false` → `exitReplay()` → **下一帧渲染恰 1 次** →
  之后 10 帧 0 次（win 态静止）→ 相机 y=1.62（第一人称眼高），不是回放的 4.5m。
  修复前副本：下一帧渲染 **0** 次（FAIL），其余前置/静止断言均 PASS。
- **备注**：只加一格脏标记，不动脏标记机制的判据；`win` 态仍保持"静止不逐帧渲染"，
  不会把 BUG-066 的性能收益退回去。

<h2 id="bug-073">BUG-073 · 困难档「最佳路径」光带实例数≈路径点数（约 1 万）</h2>

- **发现日期**：2026-11-20（来自 `检查结果说明(2026.11.20).md` 的「疑似-4」）
- **状态**：✅ 已修 / 2026-11-20
- **优先级**：P2
- **模块**：`js/player.js` → `buildPathVisual()`
- **现象**：困难档使用「最佳路径」后，地面光带的 `InstancedMesh` 实例数≈世界路径点数
  （实测 9 892~14 025），且圆盘是 `AdditiveBlending` 半透明叠加 —— 手机 GPU 的填充率代价
  比三角形数更贵，容易掉帧。与 BUG-070 是同一条操作路径（先冻十几秒，再掉帧）。
- **复现**：困难档 → 最佳路径 → 用 `player.pathGroup` 里 `InstancedMesh.count` 观察实例数。
  无头复现：`node bug070-073-verify.js --only=D --maze=<修复前副本>`（D 组 4 FAIL）。
- **根因分析**：圆盘采样循环上方写着注释"采样点（避免点太密导致三角形过多）"，
  但实现里 `var step = 1` 是**硬编码**——等于完全没有采样。困难档世界路径点之所以多，
  是因为 `toWorldPath()` 会给每个拐角插 7 个圆滑点，而蛇形迷宫里几乎每个途经点都是拐角。
- **修复**：改为**按世界距离的均匀降采样**，两条口径：
  - 世界路径点数 ≤ **2400**：保持旧观感（每个点一个圆盘，一点不变）；
  - 点数 > 2400：按 `总长度 / (2400-1)` 算采样间距，实例数被钉在上界内。
  光带的"连续不断线"由同一函数里已有的细带（ribbon，每段 2 个三角形）负责，
  终点另有独立 `endRing`，所以稀疏化不会断线、也不会丢终点标记；`worldPath` 本身与细带采样都不改。
- **验证**：D 组 12 PASS / 0 FAIL（修复前副本 4 FAIL）：

  | 输入 | 修复前实例数 | 修复后实例数 |
  |---|---|---|
  | 困难档真实「最佳路径」世界路径（9 885~9 892 点） | 9 885~9 892 | **1 391**（≤2400，且 < 原点数 1/4） |
  | 合成 10 000 点路径 | 10 000 | **1 944**（≤2400） |
  | 小路径 200 点 | 200 | **200（旧观感不变）** |
  | 细带三角形数 | (n−1)×2 | **(n−1)×2（未变）** |

  另断言：清理后 `pathGroup === null`、场景无残留 `autoPathVisual`（与 BUG-044 的释放纪律一致）。
- **备注**：`2400` 是**上界不是定值** —— 采样按世界距离做，简化后点间距不均匀
  （直道 2~5m、拐角 0.1~0.3m），保留下来的数量取决于几何，因此断言写成
  "≤2400 且 ≥1000 且 < 原点数 1/4"。真机观感（是否断线、是否够亮）**不在无头覆盖内**，需人工确认。

<h2 id="limits">覆盖边界（必须连结论一起引用）</h2>

- 以上耗时全部是 **Node/V8 桌面数字**（本机 Termux 环境），真机（尤其低端手机）会成倍放大；
  BUG-070 的断言是**上界**（3 秒），不等于真机耗时。
- 无头环境**没有真实 WebGL / GPU / 合成器**：
  - BUG-073 只证明**实例数**下降与细带几何不变，**不能证明光带看起来是否断线**；
  - BUG-072 只证明"退出回放后确实重画了一帧"，**不能证明真机上视角差异肉眼是否明显**。
- BUG-071 只证明"设置值与 DOM 控件一致"，不覆盖真实浏览器的下拉/开关渲染差异。
- 四条都**没有在真机 / 真实浏览器里复现或验收过**；发版后仍建议按
  "困难档最佳路径是否还卡、光带是否断线、退出回放背后的画面、性能模式面板"四项人工过一遍。
