## 已核实但判定为「非缺陷 / 不修」

| # | 项 | 状态 | 结论 |
|---|----|------|------|
| R4 | `js/main.js` `startGame()` 幽灵路径下 `_startPending` 提前释放 | 不修 | `.then()` 内在 `finally` 里调用 `releaseStartPending()`，导致约 60ms 加载窗口内守卫为 false。实测该窗口内 `#main-menu` 已隐藏、`#loading-screen` 覆盖，**玩家无法点到「开始游戏」**，不构成用户可达路径，仅属守卫写法不严谨。 |
| R5 | 双指同时在摇杆 + 空白区操作 | 已确认正常 | 实测两指可同时生效（`_joyId` / `_lookId` 各自独立），先抬任一指不影响另一指。 |
| R6 | 道具面板关闭依赖 ESC | 已确认正常 | 面板支持点击遮罩外部关闭（`js/ui.js`），触屏可用，不依赖键盘。 |
| R7 | 手动改档 / 导入才会出现的排行榜与最佳记录脏数据 | 已修（BUG-046 / BUG-051） | 读盘侧与写入侧口径已统一为"用时必须 > 0、步数 ≥ 0"。 |
| R8 | `js/settings.js` `reset()` 会**替换**设置对象，而 `MazeView.this.settings` 持的是旧引用（快照陈旧） | 不修（观察项） | 唯一消费者 `applyQuality()` 只用 `this.settings.shadows`；"重置设置"后 `shadows` 默认 `false`，陈旧值与生效值不可能出现"陈旧 false + 生效 true"的组合；万一出现，`main.js` 会在同一次变更里用生效值纠正墙体与渲染器，且 `sun.castShadow=false` 时地板/天花板是否接收阴影不影响画面。**无可达后果，仅记录**。 |
| R9 | `js/pathfinding.js` `lineOfSight()` 不校验**终点格**是否可通行 | 不修（观察项） | 该语义对现有调用方是**正确的**：`simplify()` 传入的路径点都是通路格；`player.js` 的 `markExplored()` 正需要"能看见墙格"才能把墙标成已探索。中间格仍逐个校验，不存在穿墙透视。 |
| R10 | `js/replay.js` 体积注释「8 局 ≈ 2 MB」偏乐观 | 不修（观察项） | 实测单帧平均 25.91 字符、单局约 228 KB 字符、8 局约 3.56 MB UTF-16 字节，仍在常见 5MB 配额内，且 `save()` 有逐级修剪兜底。只改注释无实际收益。 |
| R11 | `js/replay.js` `prune(n)` 在"只剩 1 条"时腾不出空间 | 不修（可接受降级） | 配额连 2 局都放不下（< 约 500KB，现实浏览器 ≥2MB 不存在）时新回放保存失败但保留旧回放，不丢数据。 |
| R12 | `js/maze.js:469` 的 `inst.instanceColor` 空块与 `makeGridTexture` 的未用形参 | 不修（废码） | 纯占位残留，不执行任何语句；删除只产生无意义 diff，保留不影响行为。 |

| R14 | 方向键 / 空格的 `preventDefault` 在 `e.repeat` 事件上不生效 | 不修（可接受） | 页面本身 `overflow:hidden` 不可滚动，唯一可滚动祖先是面板；在设置面板里按住方向键滚动面板属符合预期。 |
| R15 | 彩蛋验证弹窗的"合成点击"防护只覆盖 `detail === 0`（BUG-059） | 已核实正常 | 用户 2026-11-09 真机复测未复现"弹窗一闪而过"，条目关闭、未改代码。若它在别的内核上复现，把遮罩 click 守卫的 `e.detail === 0` 条件去掉即可（与 `bindShop` 的同类守卫口径一致）。 |

## 记录模板

新发现 BUG 时，复制下面的模板追加到"当前状态"上方：

```markdown
## BUG-XXX · 一句话标题

- **发现日期**：YYYY-MM-DD
- **状态**：待修
- **优先级**：P0 / P1 / P2 / P3
- **模块**：`js/xxx.js` → `functionName()`
- **现象**：用户能看到/感受到什么。
- **复现**：从哪个界面、做什么操作、观察什么。
- **根因分析**：为什么会这样。
- **修复**：改了什么（修完后填）。
- **验证**：怎么确认修好了（修完后填）。
- **备注**：修的时候要特别注意什么。

---

```

**编号规则**：接续归档文件的最大编号（当前最大为 BUG-062，下一个是 **BUG-063**）。
**状态取值**：`待修` / `待确认` / `观察中` / `已撤回` / `已修`
**优先级**：P0 立即修 / P1 版本内修 / P2 有空再修 / P3 低优先级（废码清理、微优化、文案）
