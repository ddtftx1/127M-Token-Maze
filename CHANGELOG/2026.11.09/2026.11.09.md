## Bug 修复

> 根因分析、复现、修复细节与验证过程见 `BUG/BUG(2026.11.09).md`。

- **BUG-061** · 开发者面板「音频」页点 `MG.Audio.portal()` 不发声却提示「已播放」。
  根因两半：① 它是全部 11 个音效里**唯一一个 300 Hz 以上零能量**的（180→240 Hz 纯正弦），
  而手机小喇叭在 300 Hz 以下几乎不发声——同页其它音效都在 600 Hz 以上或有谐波支撑；
  ② 面板原来是"调用成功即报已播放"，而 `audio.js` 在音频上下文挂起时会直接放弃本次发音。
  已改为：基音换三角波 + 叠加八度与十二度泛音（保留低频低鸣音色，300 Hz 以上能量翻倍），
  面板按**调用前**的上下文状态如实反馈，并在音频页显示真实 `AudioContext` 状态与解锁指引。

- **BUG-062** · 电脑 / 笔记本 / 平板上的小地图固定 168px（1080p 只占屏宽 8.7%），
  而且与难度无关 —— 根因是 `min(34vw, 168px)` 的 168px 上限在视口高 >720px 时永远生效。
  已改为随视口比例自适应（`clamp(120px, min(34vw,34vh), 320px)`，横屏矮屏单独一档），
  **手机端尺寸不变**；同时在设置面板新增「小地图大小」（自动/小/中/大）与徽标提示。

- **BUG-063** · `BUG/` 下的归档文件格式不统一：`BUG(2026.11.07).md`（1369 行 / 15 条）、
  `BUG(2026.11.08).md`、`BUG(2026.11.09).md` **完全没有目录**，`BUG(2026.10.25).md` 的 16 条
  链接还是"自动锚点"（点不动）；查历史缺陷只能 `Ctrl+F`。已给 7 个归档文件全部补齐
  `## 目录` + 显式锚点 `<h2 id="bug-0xx">`，并把这条要求**写进模板**（含自查命令）。

- **BUG-064**（2026-11-13 补修）· 对局中（已暂停）经开发者面板「环境 → 快速跳转」进入
  商店 / 排行榜 / 成就 / 签到，点「返回」会落到**主菜单** —— 主菜单盖在一局 `state === 'paused'`
  的僵尸对局上（关卡未释放，背景还是那一局的画面，HUD 与暂停菜单都不显示）。
  已改为在 UI 层按 `Game.state` 统一判定返回落点，并让面板的「主菜单」跳转在有活关卡时
  走引擎 `backToMenu()`。详见下方「[补修（2026-11-13 · BUG-064）](#补修2026-11-13--bug-064)」。

## 补修（2026-11-13 · BUG-064）

> 根因分析、复现、修复细节与修复前/后对照证据见 `BUG/BUG(2026.11.13).md`。

- **BUG-064** · 对局中（已暂停）从开发者面板「环境 → 快速跳转」进入 **商店 / 排行榜 / 成就 / 签到**，
  点「返回」会落到**主菜单** —— 主菜单盖在一局 `state === 'paused'` 的僵尸对局上：
  关卡没释放（`Game.mazeView` 还在），所以背景仍是那一局的画面，而 HUD 与暂停菜单都不显示。
  同一批里的「设置」跳转是正常的，那是 BUG-056 修过的一条 —— 本条是它的**同族遗留**
  （当时只在 `doGoto()` 里给"设置"补了来源参数，其余四条没补）。
- **修法**：返回落点改为在 UI 层**统一判定** —— 新增 `MG.UI.backFromOverlay()`
  （`Game.state === 'paused'` → 暂停菜单 + HUD，否则 → 主菜单），四条返回路径共用，
  **不再逐条传来源**（逐条传参正是上一轮漏掉四条的原因）。
  同时把开发者面板的「主菜单」跳转改为在**存在活关卡**时走引擎 `backToMenu()`
  （释放关卡、`state` 归 `menu`、清关卡遗留的雾与背景色），不再留下僵尸对局。
- **同时一并修掉同族第二处（复查发现）**：`js/main.js` 的 ESC / P 优先级链缺
  商店 / 排行榜 / 成就 三个覆盖层的分支，暂停局里按 ESC 会走 `resumeGame()` 把对局恢复成
  `'playing'` 而面板还开着（与 BUG-016 同类）；随后点「返回」还会算成落主菜单，
  对局在主菜单背后继续跑、**后台走到终点会凭空写入排行榜 / 回放 / 钱包**。
  已让 ESC / P 与鼠标点「返回」走同一条路径（`js/ui.js` 新增 `isOverlayOpen()`，
  `main.js` 链上新增分支）。
- **玩家可感知的变化**：对局中从开发者面板跳到这些界面后，返回（点按钮**或按 ESC / P**）
  都会回到**暂停菜单**（可以继续这一局），而不是"看起来回了主菜单、背景却还是对局"。
  正常玩家路径（主菜单进 → 主菜单出）行为**一字未变**；暂停菜单与胜利界面的既有按钮未动。
- **范围**：仅开发者面板可达（正常玩家没有别的入口进这四个界面），定 **P3**。
- **未修的同族第三处**：对局**已通关**（胜利界面）时从该界面的开发者入口进覆盖层，
  返回仍会落到主菜单并留下 `state === 'win'` 的僵尸对局 —— 这属于产品口径问题
  （回胜利界面，还是直接回主菜单并释放关卡？），已登记为 **BUG-065**（待确认，见 `BUG/BUG.md`），
  本次**未改**，等拍板。

## 性能优化（2026-11-14 · BUG-066）

> 根因分析、复现、修复细节与渲染计数对照见 `BUG/BUG(2026.11.14).md`。

**用户反馈**：「部分设备进游戏是不卡的，但是主界面和各种 UI 会卡、滑动会卡顿，
游戏内容探索迷宫就不会怎么卡」——注意这个"反过来卡"的分布本身就是线索：
3D 满载的场景流畅，几乎没内容的 DOM 面板反而卡。

- **① 看不见的 3D 画面仍在逐帧渲染（主因）**：`loopBody()` 结尾无条件
  `renderer.render()`，连主菜单 / 商店 / 排行榜 / 成就 / 签到 这些**全屏铺满**、
  玩家根本看不见 3D 画面的界面也照画不误；`paused` / `win` 也一样 —— 而这两种状态下
  主循环**根本不推进任何 3D 动画**，每帧重画的都是同一张静止画面。
  已改为**脏标记按需渲染**：`menu` / `paused` / `win` / 开发者面板打开时不再空转，
  只在"画面真的需要变"时画一帧（回菜单、窗口尺寸变化、设置变更、进入暂停、通关）。
  `playing` / `replay` / `loading` 保持每帧渲染，行为一点没变。
- **② 全屏毛玻璃挂在了滚动容器自己身上（卡顿的直接来源）**：`.screen` 既是全屏层、
  **又是滚动容器**，同时挂着 `backdrop-filter: blur(2px)` —— 手指每移动一帧，
  合成器都要按新的滚动偏移重算**整屏**模糊。已把毛玻璃挪到 `position:fixed` 的
  `.screen::before` 独立层（锚在视口上、滚动时纹丝不动，可被缓存成纹理），
  **2px 模糊强度原样保留**；补 `isolation: isolate` 固定层叠上下文。
  游戏内那 6 个 `blur(6px)` 的 HUD 小芯片**一行未动**（它们本来就不卡）。
- **③ 无限循环的 paint 动画 + 双层滚动抢手势（加剧）**：签到「今天」格子的呼吸动画
  动的是 `box-shadow`（10↔20px 模糊），属 paint 动画、每帧重绘，且就在带全屏毛玻璃的层里；
  已把光晕移到 `.sign-today::before`、动画只驱动 `opacity`（0.24↔0.55，2.4s，
  节奏不变），`prefers-reduced-motion` 段同步补上。另外 11 处滚动容器加了
  `overscroll-behavior: contain`，内层滚到边界不再把剩余手势传给外层
  （那是"滑到头突然跳一截"的来源，玩家也常描述成"卡"）。
- **新增真机自测入口**：开发者面板「环境」页加了「长帧 &gt;25ms」读数（10 秒滚动窗口）。
  先退出面板滑一遍菜单，再回来读数字 —— 这是无头环境量不到、只能靠真机确认的那部分。
  探针搭在常驻主循环上，不额外开定时器。
- **唯一可见变化**：签到「今天」格子的外发光颜色由写死的科技蓝改为 `var(--accent)`
  （科技主题像素级一致；地牢/森林主题下原本是"橙色边框配蓝色光晕"的错色）。
  外发光半径固定 16px、只变强弱（原来 10↔20px 会胀缩）—— 因为 box-shadow 动画本身就是
  要消掉的那个开销。不接受可改回写死蓝色（一行）。
- **不改**：任何界面结构、功能逻辑、存档格式、玩法参数。

**验证**（详见 `BUG/BUG(2026.11.14).md` 的「验证汇总」）：
`node --check` 14/14；ES5 扫描 0 命中；无头冒烟 **9/9 PASS**；
渲染计数断言（仓库外 `harness/bug066-render.js`，8 组 41 条）修复前 **PASS 36 / FAIL 5**
→ 修复后 **PASS 41 / FAIL 0**；BUG-064 的 264 条断言 **无回退**。
关键计数：菜单 60 帧 **60 → 0**、`paused` 静止期 20 帧 **20 → 0**、`win` 静止期 **20 → 0**、
开发者面板打开期间 **20 → 0**，而 `playing` **30 → 30**、`replay` **30 → 30**、
回菜单 **1 次**（且渲染时 `mazeView === null`，画的是纯背景不是旧迷宫）、
resize / 切主题各 **1**、切画质 **2**（重建渲染器自带首帧）。

> 边界如实声明：jsdom **没有真实合成器 / 布局引擎 / GPU**，上述只能证明
> "我们不再要求 GPU 画一张没人看的图"这一可观测事实，**不能证明**真机滑动帧率已提升，
> 也不能证明浏览器端 `backdrop-filter` 不再重算 —— CSS 三项收益只能由真机滑动确认。
