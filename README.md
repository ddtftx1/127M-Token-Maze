# 🎮 3D迷宫探险 (127M-Token-Maze)

> **“本项目的所有代码由 AI 编写，所有提示词也由 AI 编写。人类（我）只负责提出异想天开的需求、测试、截图报错、以及按下回车键。”**

这是一个完全在浏览器端运行的 Web 3D 第一人称迷宫游戏。它没有使用任何外部 3D 模型和图片贴图，所有场景、墙体纹理、音效均由代码动态生成。

## 🕹️ 游戏特色 (Features)
*   🎯 **第一人称控制**：移动端支持虚拟摇杆，PC 端支持 WASD 移动与 Pointer Lock 鼠标视角锁定。
*   🧭 **智能自动寻路**：内置 A* 算法（带二叉最小堆优化），支持“最佳路径”（顺路拾取金币）与“最快路径”（直奔终点）。
*   👻 **幽灵对战系统**：系统会自动记录你的通关录像。下次挑战相同种子时，可以召唤过去的“幽灵”和自己同台竞技。
*   🗺️ **探索与解锁**：初始小地图是锁定的。在迷宫里找到“地图卷轴”后道具进背包，
    需要在道具面板（F）中主动使用才会解锁小地图，多了“发现 → 使用”两个决策点。
*   🏪 **商店与道具**：通关和捡金币可以购买道具，甚至买断金币收益加成。
*   📅 **每日签到**：主菜单「每日签到」入口（未领取时带红点角标），每天可领一次随机奖励——
    常规 5~10 金币，每连签 7 天额外保底一件道具，另有 8% 宝箱与 1% 大吉（金币 ×3）。
    断签会清零回第 1 天，可在商店买「签到护符」自动抵消一次漏签（最多保住漏签 5 天）。

### 目标环境

| 环境 | 状态 |
|------|------|
| **Win7 / Chrome 109**（Win7 上最后能装的 Chrome 版本）/ Chromium Edge 79+ | 支持，含图标与布局降级 |
| 现代 Chrome / Edge / Firefox / Safari | 支持 |
| iOS Safari / Android Chrome（含横屏矮屏） | 支持 |
| 无 WebGL 的环境 | 不支持，启动时弹致命错误面板并提供"重新加载"按钮 |

> **口径订正（2026-11-07）**：本文档此前写的是「Chrome 49+，Win7 上最后能装的就是 49」，
> 其中「49」是**错的** —— Win7 上最后能装的是 **Chrome 109**（用户当面纠正）。
> 活文档已统一改为 109；`CHANGELOG/` 与 `BUG()` 的历史归档按「只增不改」保留原文，
> 订正说明见 `BUG/BUG(2026.11.07).md`。

### 运行方式

- **双击 `index.html`（`file://`）** 或放到任意静态服务器下，行为一致；
- 无构建步骤、无 npm、无打包：改完源码刷新即可；
- **不发起任何本地文件请求**：图标是 `js/icons.js` 里的内联字符串，
  所以不存在 `file://` 下的 CORS 问题；Three.js 也是本地 `<script>` 引入。

### 老内核降级（Win7 / Chrome 109）

启动时 `applyLegacyClasses()` 用 `CSS.supports()` 做**能力检测**（不猜 UA），
不支持则给 `body` 挂对应 class，`css/style.css` 末尾有配套降级规则：

| class | 触发条件 | 降级后的表现 |
|-------|----------|--------------|
| `legacy-env` | 不支持 `env(safe-area-inset-*)` | 安全区按 `0px` 处理（否则整条 `calc()` 失效，面板贴边 + 多出白滚动条） |
| `legacy-inset` | 不支持 `inset` 简写 | 样式表中已全部展开为 `top/right/bottom/left` |
| `legacy-gap` | flex 容器的 `gap` 不可用 | 相邻兄弟选择器补 `margin` |
| `legacy-dvh` | 不支持 `100dvh` | 由同规则内保留的 `100vh` 声明接管 |

此外，**横屏紧凑布局对桌面同样生效**：`@media (orientation: landscape) and (max-height: 720px)`
只看"横屏 + 视口矮"，不再限定触屏设备。
（此前曾用 `(hover: none) and (pointer: coarse)` 把桌面排除在外 —— 那是修 BUG-018 时加的限定，
副作用是 Win7 上桌面永远回退到竖屏口径，已于 **BUG-030** 按用户要求还原为桌面共用；
开发者面板的「左侧竖排页签」因为没有高度上限，仍保留触屏限定，避免大屏桌面被挤掉正文宽度。）

**关于 ES2015 API 的说明**：
代码的核心语法严格遵守 ES5（`var` / `function` / IIFE）。但在极少数底层实现中，使用了部分
Chrome 109 原生支持的 ES2015 API（例如 `js/ui.js` 中的 `new Promise`，以及 `TypedArray`
（`Uint8Array` / `Int32Array`）的 `.fill()` 方法），因为它们并未破坏老内核的运行环境，
故未引入额外的 polyfill 处理。

### 已知限制

- `legacy-gap` 用 `CSS.supports('gap', ...)` 只能判断"属性是否存在"，分不清 flex 与 grid。
  Chrome 57~83 的 grid 已有 `gap`、flex 还没有，会被判为"支持"，
  表现为 flex 子元素无间距（不错位）。目标环境 Chrome 109 原生支持 flex `gap`，
  所以该 class 不会被挂上；这段逻辑只为更老的内核保留。
- 图标是彩色位图风格矢量图，不随主题换色；深色主题下图标保持自身的彩色
  （色盲友好模式同样不重绘图标配色）。

## 🔄 赛博套娃开发架构
本项目采用了一种极其奇特的“多 Agent 协同”开发模式：

```text
① 我：提出需求 / 目标
        ↓
② AI1：生成提示词 vN
        ↓
③ 我：人工转交提示词 vN 给 AI2
        ↓
④ AI2：写代码，并启动本地服务器
        ↓
⑤ 本地服务器：运行 3D 迷宫游戏
        ↓
⑥ AI2：获取运行/测试结果
        ↓
⑦ AI2：把“代码文件 + 测试结果”发给我
        ↓
⑧ 我：把代码和测试结果回灌给 AI1
        ↓
⑨ AI1：审查代码，输出 Bug 清单 + 修复建议
        ↓
⑩ 我：收到 Bug 建议，要求 AI1 生成下一轮提示词
        ↓
⑪ AI1：生成提示词 vN+1
        ↓
⑫ 我：人工转交 vN+1 给 AI2
        ↓
    回到第④步，循环

AI1 不直连 AI2；
所有跨 AI 的传递都经过“我”；
本地服务器只和 AI2 交互；
测试结果先到“我”，再由“我”回灌给 AI1。
```
